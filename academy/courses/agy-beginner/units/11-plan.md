# 11강. AI의 계획에서 과한 일을 덜어내기

유정근 · 마이웨이 아카데미 | C1 AGY 입문

## 오늘의 목표

AGY가 보여 준 계획서(Implementation Plan)를 한 줄씩 읽고, 부탁하지 않은 단계를 빼 달라고 말한 뒤, 필요한 단계만 승인합니다.

## 먼저 이해하기

AI는 친절하려다 부탁하지 않은 일까지 계획에 넣곤 합니다. "안내문 하나"를 부탁했는데 "웹에 올리기", "폴더 전체 정리"까지 들어가는 식입니다. 계획서를 승인한다는 것은 그 안의 모든 줄에 동의한다는 뜻이므로, 승인 전에 덜어냅니다.

계획서를 읽을 때 네 가지를 찾습니다.

| 찾을 것 | 뜻 | 예 |
| --- | --- | --- |
| 입력 | 무엇을 읽고 일하는가 | `practice` 폴더의 `memo.txt` |
| 출력 | 무엇이 새로 생기는가 | 새 파일 `notice_draft.md` 1개 |
| 제외 범위 | 하지 않을 일 | 인터넷 게시, 다른 파일 수정·삭제 |
| 완료 기준 | 무엇을 보면 끝났다고 할까 | 파일을 열어 원문 메모와 대조 |

계획서를 고치는 방법은 두 가지입니다(공식 도움말 기준).

- 채팅으로 말하기: 채팅 입력칸에 "2번과 3번 단계는 빼 줘" 라고 보냅니다. 가장 쉬운 방법입니다.
- 계획서에 메모 달기: 계획 문서에서 고치고 싶은 문장을 마우스로 끌어 선택하면 그 자리에 댓글(코멘트)을 달 수 있습니다. 계획 문서 위쪽의 'Review' 단추를 누르면 달린 댓글을 모아 보고 보낼 수 있습니다.

다 고쳤으면 'Proceed'(진행) 단추를 눌러 승인합니다. 'Proceed'는 채팅 안과 계획 문서 위쪽 두 곳에 나타납니다. (화면의 글자는 버전에 따라 조금 다를 수 있습니다.) 'Proceed'를 누르기 전에는 파일이 만들어지지 않습니다.

공식 자료: [구현 계획서 검토](https://antigravity.google/docs/implementation-plan)

## 실제 기록에서 배운 한 줄

실제 계획서 대화에서는 파일을 만든 뒤 게시·저장소 작업을 별도 요청으로 이어 갔습니다. 한 번의 초안 요청에 후속 작업까지 묶지 않고 범위를 나누는 방식이었습니다. 이 수업에서도 "만들기"와 "내보내기"를 한 계획에 섞지 않습니다.

## 가상 예시로 직접 해 보기

아래 모임·자료·파일 이름은 학습용 가상 설정입니다. 실제 고객 자료나 이력을 넣지 않습니다.

준비: `practice` 폴더에 4강의 가상 `memo.txt` 가 있는지 왼쪽 파일 목록에서 확인합니다. 없으면 먼저 채팅에 "practice 폴더에 memo.txt 를 만들고 '작은 배움 모임, 대상 성인, 종이로 실습, 날짜 미정' 네 줄을 적어 줘" 라고 보내 만들어 둡니다.

**1단계 — 계획을 받기**

1. 채팅 입력칸 근처의 모드 단추가 'Planning'인지 봅니다(10강). 아니면 'Planning'으로 바꿉니다.
2. 아래 "AI에게 건네는 말"의 첫 번째 글을 보냅니다. 이 글은 일부러 넓게 부탁하는 글입니다.
3. 계획 문서가 열릴 때까지 기다립니다. 아직 'Proceed'를 누르지 않습니다.

이렇게 보이면 됩니다: 번호나 제목이 붙은 계획 문서가 보이고, 안에 여러 단계가 적혀 있습니다.

✖ 계획서 없이 바로 파일이 만들어졌다면: 모드가 Fast였거나 검토 방식이 Always Proceed입니다(10강). 만들어진 파일은 그대로 두고, 모드를 확인한 뒤 다시 보냅니다.

**2단계 — 한 줄씩 표시하기**

1. 종이에 계획의 단계를 번호대로 옮겨 적습니다.
2. 각 줄 옆에 ○(필요함) 또는 ×(부탁 안 함)를 표시합니다.
3. 예를 들어 계획이 "① 메모 읽기 ② 안내문 파일 만들기 ③ 웹에 게시 ④ practice 폴더 전체 정리"라면, ③과 ④가 ×입니다.
4. 위 표의 네 가지(입력·출력·제외 범위·완료 기준) 중 계획에 빠진 것도 적습니다.

**3단계 — 덜어 달라고 말하기**

1. 채팅 입력칸에 아래 두 번째 글을 보냅니다. ×로 표시한 단계 번호를 내 계획에 맞게 바꿔 씁니다.
2. 또는 계획 문서에서 ×인 문장을 마우스로 끌어 선택하고, 나타나는 댓글 칸에 "이 단계는 빼 주세요"라고 적은 뒤 'Review' 쪽에서 보냅니다.
3. AGY가 고친 계획을 다시 보여 줄 때까지 기다립니다.

이렇게 보이면 됩니다: 새 계획에서 ×였던 단계가 사라지고 "하지 않을 일"에 게시·폴더 정리가 적혀 있습니다.

**4단계 — 필요한 만큼만 승인하기**

1. 새 계획을 다시 한 줄씩 읽고, 모든 줄이 ○인지 확인합니다.
2. 'Proceed'를 누릅니다.
3. 끝났다는 보고가 오면 왼쪽 파일 목록에서 새 파일(예: `notice_draft.md`)을 눌러 열고, `memo.txt` 와 내용이 맞는지 봅니다.
4. 폴더에 부탁하지 않은 파일이 새로 생기거나 기존 파일이 바뀌지 않았는지 목록을 훑어봅니다.

## AI에게 건네는 말

> **어디에 입력하나요:** 바탕화면이나 시작 메뉴에서 'Antigravity'를 눌러 AGY를 엽니다. 작업 폴더가 열려 있는지 먼저 봅니다(C1 3강). 화면 아래쪽의 채팅 입력칸(에이전트에게 말을 거는 칸)을 누르고, 아래 글을 붙여 넣은 뒤 `Enter` 로 보냅니다. AGY가 대화 안에 계획이나 확인 카드를 먼저 보여 주면, 바로 승인하지 말고 무엇을 하겠다는지 읽은 뒤 결정합니다(C1 9강).

1단계에서 보낼 글 (일부러 넓게 쓴 부탁):

> memo.txt로 모임 안내를 알아서 전부 준비해 줘. 먼저 계획을 보여 줘.

3단계에서 보낼 글:

> 계획 중 ③ 웹 게시와 ④ 폴더 전체 정리는 빼 줘. 남길 일은 memo.txt를 읽고 새 파일 notice_draft.md 하나를 만드는 것과, 끝난 뒤 원문과 대조한 결과를 보여 주는 것뿐이야. 기존 파일은 바꾸지 마. 고친 계획을 다시 보여 주고 내 승인을 기다려.

답을 읽는 법: 고친 계획이 오면 "만들 파일"이 한 개인지, "하지 않을 일"에 게시와 폴더 정리가 적혀 있는지부터 봅니다. 둘 중 하나라도 없으면 'Proceed'를 누르지 말고 한 번 더 말합니다.

## 손에 남길 것과 완료 확인

**수정한 계획과 범위 승인문**

- 처음 계획의 단계 목록과 ○/× 표시 (종이 또는 메모장)
- 내가 보낸 덜어내기 글 한 개
- 승인 뒤 생긴 `notice_draft.md` 한 개

완료 기준: ×로 표시한 단계가 고친 계획에서 빠진 것을 확인한 뒤에 'Proceed'를 눌렀고, 만들어진 파일을 직접 열어 보았습니다. 부탁하지 않은 변화가 있었다면 그 내용을 적고 12·13강에서 다룹니다.
