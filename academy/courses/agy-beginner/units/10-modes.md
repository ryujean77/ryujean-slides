# 10강. 계획부터 할까, 바로 실행할까

유정근 · 마이웨이 아카데미 | C1 AGY 입문

## 오늘의 목표

Planning과 Fast의 차이를 알고 과제에 맞게 고른다.

## 먼저 이해하기

Planning은 계획을 세우는 방식, Fast는 별도 계획 단계 없이 바로 수행하는 방식이다. Planning에서도 검토 설정을 확인한다.

| 구분 | 뜻 |
| --- | --- |
| Planning / Fast | 계획을 충분히 세운 뒤 수행할지, 별도 계획 단계 없이 수행할지 |
| Request Review | Planning에서 제안을 사람이 검토하도록 하는 설정 |
| Local / New Worktree | 어느 작업 공간에서 작업할지에 관한 별도 선택 |

Planning을 고른 사실만으로 매번 승인을 기다린다고 생각하지 않습니다. 검토 정책도 확인합니다. Fast도 권한 통제를 없애는 설정은 아닙니다. [공식 계획·실행 방식](https://antigravity.google/docs/artifact-review)

## 실제 기록에서 배운 한 줄

실제 사용자 화면의 보안 메뉴가 설명과 달라 진행이 막혔고, 사용자가 화면 문구를 되물은 뒤 폴더 연결을 확인했다. 모드도 보이는 이름과 설정을 대조하며 선택한다.

## 가상 예시로 직접 해 보기

아래 모임·자료·파일 이름은 학습용 가상 설정입니다. 실제 고객 자료나 이력을 넣지 않습니다.

1. 새 안내 페이지 제작과 기존 문장 한 곳 수정 중 먼저 계획이 필요한 작업을 고른다.
2. Planning과 Request Review 설정을 확인하고 읽을 파일·만들 파일·검사 순서를 받는다.
3. Fast는 복구 사본이 있는 연습 파일의 작은 수정에만 비교해 본다. Local·Worktree는 작업 위치 방식으로 별도 개념임을 구분한다.

## AI에게 건네는 말

> 먼저 계획만 제시해 줘. 읽을 자료, 만들 파일, 검사할 항목을 세 줄로 적고 기다려. 계획 승인과 실제 실행 권한은 따로 확인할게.

## 손에 남길 것과 완료 확인

**모드 선택표**

Planning과 Fast의 차이를 알고 과제에 맞게 고른다. 이 행동을 직접 수행했는지 확인합니다. 결과 파일이 있는 수업은 파일을 열어 확인하고, 판단 수업은 선택한 이유를 한 문장으로 적습니다. 하지 못한 단계는 성공한 것처럼 기록하지 않고 보완할 행동을 남깁니다.
