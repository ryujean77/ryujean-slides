# 5강. 인박스를 지켜보는 자동화 — 파일이 들어오면 일이 시작된다

유정근 · 마이웨이 아카데미 | C3 업무 자동화
척추: 12블럭 B10

## 오늘의 목표

드라이브 인박스 폴더를 **정해진 간격으로 확인하는** 자동화의 원리를 이해하고, "새 파일을 찾는다 → 처리한다 → 성공했을 때만 옮긴다"는 세 규칙을 설계서에 적습니다. 실습에서는 드라이브에 흐름 폴더를 만들고, 앱스 스크립트 편집기를 처음 열어 화면을 둘러보고, AGY에게서 코드 <strong>계획</strong>을 받아 읽습니다. 오늘은 코드를 실행하지도, 트리거를 켜지도 않습니다.

## 먼저 이해하기

C2에서 만든 `00_inbox`는 지금까지 사람이 들여다보는 우편함이었습니다. 오늘은 여기에 **지켜보는 사람을** 한 명 붙입니다. 파일이 들어오면 누가 시키지 않아도 일이 시작되게 하는 것입니다.

지켜보는 방식은 두 가지입니다.

- <strong>즉시 감지</strong> — 컴퓨터에 늘 켜 둔 프로그램이 폴더를 붙들고 있다가, 파일이 생기는 순간 반응합니다. 그 컴퓨터가 꺼지면 감시도 멈춥니다.
- <strong>정기 확인</strong> — 정해진 간격마다 폴더를 열어 보고, 지난번 이후 새로 생긴 파일이 있으면 처리합니다.

수강생 실습은 정기 확인으로 합니다. 도구는 <strong>앱스 스크립트</strong>(Apps Script — 구글 드라이브·문서·시트·Gmail을 정해진 규칙대로 움직이게 하는, 구글이 무료로 주는 코드 도구)입니다. 앱스 스크립트는 구글의 컴퓨터에서 돌기 때문에 내 PC가 꺼져 있어도 움직입니다.

앱스 스크립트에서 "때가 되면 저절로 실행되게 하는 설정"을 <strong>트리거</strong>라고 합니다(방아쇠라는 뜻). 이 가운데 내가 직접 만들어 켜는 것을 공식 문서는 <strong>설치형 트리거</strong>라고 부릅니다. 공식 문서가 안내하는 설치형 트리거에는 시트·문서·설문지·캘린더에서 무언가 바뀔 때 반응하는 것과, <strong>시간 기반 트리거</strong>(정해진 시각이나 간격마다 실행되는 트리거)가 있습니다. "드라이브 폴더에 파일이 추가되면" 반응하는 트리거는 목록에 없습니다. 그래서 시간 기반 트리거로 폴더를 정기 확인합니다. 간격은 1분마다부터 한 달에 한 번까지 고를 수 있습니다.

트리거가 부르는 대상은 <strong>함수</strong>(코드 안에서 "이 이름을 부르면 이 일을 한다"고 이름 붙여 둔 한 덩어리)입니다. 예를 들어 `checkInbox` 라는 함수를 15분마다 부르게 하는 식입니다.

정기 확인이 안전하려면 세 규칙이 필요합니다.

- **새 파일만 찾는다**: 이미 처리한 파일을 또 처리하지 않도록, 처리한 파일은 다른 폴더로 옮기거나 기록 시트에 이름을 남깁니다.
- **처리한다**: 1건씩, 원본은 건드리지 않고 결과는 새 파일로 만듭니다.
- **성공했을 때만 옮긴다**: "처리함" 표시는 결과 파일이 실제로 생긴 뒤에 합니다. 순서가 뒤집히면 실패한 파일이 처리된 것으로 숨어 버립니다.

비유하자면 아파트 경비실의 택배 보관함 순찰입니다. 경비원은 택배가 도착하는 순간을 지켜보지 않습니다. 한 시간마다 보관함을 돌며 새로 온 것을 장부에 적고, 주인에게 전달된 것만 "전달 완료"에 줄을 긋습니다. 전달하지 못한 택배에 먼저 줄을 그으면, 그 택배는 영영 보관함 구석에 남습니다.

## 강사의 시스템에서

강사의 인박스는 즉시 감지 방식입니다. 휴대폰 통화 녹음이 드라이브에 자동으로 올라오면, 강사의 PC에서 늘 돌고 있는 <strong>감시 프로그램</strong>이 이를 알아채고 받아쓰기와 초안 작성을 시작합니다. 초안 한 건에 68~114초가 걸렸습니다.

이 방식에서 얻은 교훈 세 가지는 정기 확인에도 그대로 통합니다.

첫째, **켤 때 한 번 훑는다.** 감시 프로그램을 다시 켰을 때, 꺼져 있던 동안 들어와 대기하던 녹취 2건을 먼저 찾아 처리했습니다. 지켜보는 눈은 반드시 꺼지는 순간이 있습니다. 다시 켜질 때 밀린 것부터 보는 규칙이 없으면, 꺼져 있던 시간에 들어온 파일은 아무도 모르게 남습니다.

둘째, **"처리함" 표시는 성공 뒤에.** 코드 점검에서 가장 무서운 결함이 여기서 나왔습니다. AI 처리가 성공하기 전에 처리 이력을 먼저 적는 줄이 있었습니다. 처리가 실패해도 이력에는 남으니, 다음 순찰 때 그 파일은 "이미 한 것"으로 건너뜁니다. 보고서의 표현으로는 "통화 1건이 조용히 증발"하는 구조였습니다.

셋째, **시험 파일도 진짜로 처리된다.** 자동 감지가 되는지 확인하려고 넣은 시험 파일 세 개가 그대로 초안이 되어 결재판에 올라왔습니다. 업무 내용이 없는 초안 세 장이 결재를 기다린 셈입니다. 시험할 때는 파일 이름에 `TEST_`를 붙이고, 흐름에서 이 <strong>접두사</strong>(이름 맨 앞에 붙이는 약속된 글자)를 걸러 내는 규칙을 함께 둡니다.

인박스 62건 가운데 미처리는 4건이었습니다. 지켜보는 쪽은 잘 돌았습니다. 막힌 곳은 늘 그다음, 사람이 결재하는 자리였습니다(2강).

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다. 오늘은 코드를 직접 쓰지 않고, AI가 쓴 계획을 **읽고 승인할지 정하는** 연습까지 합니다.

**가. 드라이브에 흐름 폴더 만들기** (PC, 크롬)

1. PC에서 크롬을 열고 주소창에 `https://drive.google.com` 을 입력해 들어갑니다. 왼쪽 목록에서 '내 드라이브'를 누릅니다.
   → 이렇게 보이면 됩니다: 가운데에 내 드라이브의 폴더와 파일 목록이 보입니다.
2. 왼쪽 위의 '+ 새로 만들기' 버튼을 누르고, 열린 메뉴에서 '새 폴더'(또는 '폴더')를 누릅니다.
   → 이렇게 보이면 됩니다: '새 폴더'라는 작은 창에 이름 칸이 있습니다.
3. 이름 칸에 `C3_자동화` 를 입력하고 '만들기'를 누릅니다.
4. 목록에 생긴 `C3_자동화` 폴더를 두 번 눌러 들어갑니다.
   → 이렇게 보이면 됩니다: 화면 위쪽 경로가 '내 드라이브 > C3_자동화' 로 바뀌고, 가운데는 비어 있습니다.
5. 이 안에서 2~3번을 네 번 되풀이해 폴더 네 개를 만듭니다: `00_inbox`(새로 들어온 원본), `01_draft`(AI가 만든 초안), `90_done`(처리가 끝난 원본), `99_error`(처리하다 실패한 원본).
   ✖ 폴더가 `C3_자동화` 밖(내 드라이브 바로 아래)에 생겼다면: 그 폴더를 마우스 오른쪽 단추로 누르고 '정리' → '이동' → `C3_자동화` 를 고른 뒤 '이동'을 누릅니다.
6. 같은 `C3_자동화` 안에서 '+ 새로 만들기' → 'Google 스프레드시트' 를 누릅니다. 새 시트가 열리면 왼쪽 위 '제목 없는 스프레드시트'를 눌러 `처리기록` 으로 바꿉니다. 첫 줄 A1~D1 칸에 차례로 `시각`, `파일 이름`, `결과`, `오류 내용` 을 적습니다. 실패가 생기면 코드가 여기에 한 줄씩 적게 됩니다.
7. 시트 탭을 닫고 드라이브 탭으로 돌아옵니다.
   → 이렇게 보이면 됩니다: `C3_자동화` 안에 폴더 네 개와 `처리기록` 시트 하나가 보입니다.

**나. 규칙을 설계서에 적기**

8. 4강의 `C3_설계서_v02` 문서를 열고 "3 입력" 아래에 세 규칙을 자기 말로 씁니다. 윤하람 씨: "15분마다 `C3_자동화/00_inbox` 를 본다. `TEST_`로 시작하지 않는 새 파일만 1건씩 처리한다. 초안이 `01_draft`에 생긴 것을 확인한 뒤에만 원본을 `90_done`으로 옮긴다. 실패하면 원본을 `99_error`로 옮기고 `처리기록` 시트에 사유를 적는다."
9. 확인 간격을 정합니다. 앱스 스크립트 공식 문서의 <strong>할당량</strong>(무료로 쓸 수 있는 한도)을 보면, 개인 구글 계정(gmail.com)은 트리거로 도는 실행 시간이 하루 합계 90분, 한 번 실행은 6분까지입니다. 15분 간격이면 하루 96번 도는데, 빈 인박스를 확인하는 데는 몇 초면 끝나므로 한도 안에 넉넉히 들어갑니다. 윤하람 씨는 수업 메모가 급하지 않으므로 15분을 골랐습니다.

**다. 앱스 스크립트 편집기를 처음 열어 보기** (PC, 크롬 — 둘러보기만)

10. 드라이브 탭에서 `C3_자동화` 폴더 안에 있는지 확인합니다(화면 위 경로가 '내 드라이브 > C3_자동화'). 이 안에서 만들어야 스크립트 파일이 이 폴더에 함께 놓입니다.
11. 왼쪽 위 '+ 새로 만들기'를 누르고, 메뉴 아래쪽의 '더보기'에 포인터를 올립니다. 옆으로 열린 목록에서 'Google Apps Script'를 누릅니다.
    → 이렇게 보이면 됩니다: 새 탭이 열리며 <strong>스크립트 편집기</strong>(앱스 스크립트 코드를 쓰고 저장하고 실행하는 화면)가 나타납니다. 왼쪽 위에 '제목 없는 프로젝트', 가운데 흰 칸에 `function myFunction() {` 과 `}` 두 줄이 보입니다.
    ✖ '더보기' 안에 'Google Apps Script'가 보이지 않으면: 새 탭(`Ctrl + T`) 주소창에 `https://script.google.com/create` 를 입력해 들어갑니다. 같은 편집기가 새 프로젝트로 열립니다. 이 경우 스크립트 파일은 '내 드라이브' 바로 아래에 생기므로, 14번 뒤에 드라이브에서 마우스 오른쪽 단추 → '정리' → '이동'으로 `C3_자동화` 에 옮깁니다. 기관 계정이라 편집기가 아예 열리지 않으면 관리자가 막아 둔 것일 수 있으니, 개인 구글 계정으로 실습합니다.
    다른 길 하나: 구글 시트를 열어 위쪽 메뉴 '확장 프로그램' → 'Apps Script' 를 눌러도 편집기가 열립니다. 이렇게 만든 스크립트는 그 시트에 붙은 스크립트가 됩니다. 이 과정에서는 드라이브에서 따로 만든 스크립트를 씁니다.

12. 왼쪽 위 '제목 없는 프로젝트' 글자를 누릅니다. 이름 칸에 `인박스감시_v01` 을 입력하고 '이름 바꾸기'를 누릅니다. 이 이름 전체를 <strong>프로젝트</strong>(앱스 스크립트에서 코드 파일과 설정을 한데 묶은 단위)라고 부릅니다.
    → 이렇게 보이면 됩니다: 왼쪽 위 이름이 `인박스감시_v01` 로 바뀝니다.
13. 화면을 구역별로 둘러봅니다. 아무것도 누르지 않고 보기만 합니다.
    - **맨 왼쪽 세로 아이콘 줄**: 위에서부터 '개요'(동그라미 속 i), '편집기'(`< >` 모양), '트리거'(알람 시계 모양), '실행'(줄 세 개 옆에 재생 ▶ 모양), '프로젝트 설정'(톱니바퀴). 아이콘 위에 포인터를 올리면 이름이 뜹니다.
    - **그 오른쪽 '파일' 목록**: `Code.gs` 라는 파일 하나가 있습니다. 코드는 이 파일에 씁니다.
    - **가운데 넓은 흰 칸**: 코드를 쓰는 곳입니다.
    - **가운데 위쪽 도구 줄**: 왼쪽부터 되돌리기·다시 하기 화살표, '프로젝트 저장'(디스크 모양), '실행'(▷), '디버그', 함수 이름이 적힌 선택 칸(지금은 `myFunction`), '실행 로그'.
14. 편집기 탭은 닫아도 됩니다. 저장할 것이 없고, 프로젝트는 드라이브 `C3_자동화` 안에 `인박스감시_v01` 로 남습니다. 드라이브 탭을 새로 고침(`F5`)하면 보입니다.

**라. AGY에게 코드 계획 받기** (PC, AGY)

15. AGY를 열고, 아래 "AI에게 건네는 말"의 첫 번째 글을 보냅니다. 입력칸 근처의 모드 단추가 'Planning'(계획 모드, C1 10강)인지 먼저 확인합니다. 오늘은 AGY가 파일을 만들 일이 없으니, 작업 폴더는 C1에서 쓰던 `practice` 프로젝트여도 됩니다.
    → 이렇게 보이면 됩니다: AGY가 코드를 쓰지 않고 "이런 순서로 하겠다"는 계획을 대화 안에 보여 줍니다.
    ✖ 계획 없이 코드가 바로 나왔다면: 그 코드는 복사하지 않습니다. "코드는 아직 쓰지 말고 계획부터 보여 줘"라고 다시 보냅니다.
16. 받은 계획에서 세 가지를 눈으로 찾아 설계서 여백에 ○/× 로 적습니다. ① 원본을 옮기는 단계가 결과 파일을 확인하는 단계보다 **뒤에** 있는가 ② 실패했을 때 가는 길(`99_error`, `처리기록`)이 있는가 ③ `TEST_` 파일을 거르는가.
17. 셋 중 하나라도 × 이면 승인하지 않고 두 번째 글로 짚어 달라고 한 뒤, 고쳐 달라고 요청합니다.
18. 계획이 세 가지를 모두 갖추면, 그 계획을 끌어 선택해 복사하고 설계서 맨 아래에 "코드 계획 v1"이라는 제목으로 붙여 둡니다. 코드 작성·붙여 넣기·실행·트리거는 8강에서 합니다.

## AI에게 건네는 말

> **어디에 입력하나요:** 바탕화면이나 시작 메뉴에서 'Antigravity'를 눌러 AGY를 엽니다. 작업 폴더가 열려 있는지 먼저 봅니다(C1 3강). 화면 아래쪽의 채팅 입력칸(에이전트에게 말을 거는 칸)을 누르고, 아래 글을 붙여 넣은 뒤 `Enter` 로 보냅니다. AGY가 대화 안에 계획이나 확인 카드를 먼저 보여 주면, 바로 승인하지 말고 무엇을 하겠다는지 읽은 뒤 결정합니다(C1 9강).

첫 번째 글 (15번):

> 구글 앱스 스크립트로 드라이브 폴더 감시 코드를 만들려 한다. 아직 코드를 쓰지 말고 계획부터 보여 줘. 폴더는 모두 내 드라이브의 'C3_자동화' 폴더 안에 있다. 규칙: ① 시간 기반 트리거로 15분마다 '00_inbox' 폴더를 확인한다 ② 이름이 'TEST_'로 시작하는 파일은 건너뛴다 ③ 한 번에 한 파일씩 처리한다 ④ 결과 파일이 '01_draft'에 실제로 생긴 것을 확인한 뒤에만 원본을 '90_done'으로 옮긴다 ⑤ 실패하면 원본을 '99_error'로 옮기고 '처리기록' 시트에 시각·파일 이름·결과·오류를 한 줄 남긴다 ⑥ 원본 파일은 지우지 않는다. 처리 단계는 지금은 '초안 만들기 자리'로 비워 둬. 나는 코드를 처음 다루니, 각 단계를 쉬운 말로 한 줄씩 설명해 줘.

답을 읽는 법: 계획이 번호 목록으로 오면 16번의 세 가지를 찾습니다. 모르는 말(예: "Iterator", "try-catch")이 나오면 같은 입력칸에 "○○가 무슨 뜻이야? 쉬운 말로" 라고 묻습니다.

두 번째 글 (17번 — 계획을 한 번 더 짚게 할 때):

> 네 계획에서 원본을 옮기는 단계가 결과 확인보다 뒤에 있는지, 실패했을 때의 길이 모든 단계에 있는지 한 줄씩 짚어서 설명해 줘. 내가 읽고 승인하기 전에는 코드를 쓰지 말고 트리거도 설치하지 마.

답을 읽는 법: 설명 가운데 "먼저 옮긴 뒤 확인한다"처럼 순서가 뒤집힌 줄이 있으면 "그 순서를 바꿔 줘"라고 보냅니다. 모든 줄이 "확인 → 옮김" 순서이면 18번으로 넘어갑니다.

## 손에 남길 것과 완료 확인

**드라이브 흐름 폴더, 인박스 감시 규칙 3줄, 검토한 코드 계획**

- [ ] 드라이브 `C3_자동화` 안에 `00_inbox` · `01_draft` · `90_done` · `99_error` 폴더와 `처리기록` 시트가 있다
- [ ] 설계서에 확인 간격(15분)과 세 규칙(새 파일만·1건씩·성공 뒤에 옮기기), 실패 시 가는 곳이 적혀 있다
- [ ] `C3_자동화` 안에 앱스 스크립트 프로젝트 `인박스감시_v01` 이 있고, 편집기의 다섯 구역(왼쪽 아이콘 줄·파일 목록·코드 칸·도구 줄·실행 로그)을 찾아보았다
- [ ] AGY 계획에서 16번의 세 가지를 직접 찾아 ○/× 로 적었다
- [ ] 트리거를 켜지 않았고, 코드를 실행하지 않았다

찾지 못한 항목이 있으면 "승인 보류 — 이유"를 설계서에 적어 둡니다. (화면의 글자는 버전에 따라 조금 다를 수 있습니다.)
