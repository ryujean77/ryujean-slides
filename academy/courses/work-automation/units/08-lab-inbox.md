# 8강. 실습 ② 인박스에서 초안까지 한 바퀴

유정근 · 마이웨이 아카데미 | C3 업무 자동화

척추: 12블럭 B10

## 오늘의 목표

드라이브의 인박스 폴더에 메모 한 건을 넣고, AGY가 7강의 고정 양식으로 초안을 만들어 "결재 대기" 폴더에 놓기까지 한 바퀴를 직접 돌립니다. 앞부분(가)은 사람이 방아쇠를 당기는 자동화입니다. 손으로 돈 한 바퀴가 맞는 것을 확인하면, 뒷부분(나)에서 5강의 감시 코드를 앱스 스크립트 편집기에 붙여 넣고, 한 번 손으로 실행해 <strong>권한 승인</strong>(이 코드가 내 드라이브를 다뤄도 된다고 구글 계정으로 허락하는 절차)을 마친 뒤, **트리거를 켜서** 사람이 없어도 인박스가 초안 자리까지 움직이게 합니다.

## 먼저 이해하기

5강에서 설계한 감시 자동화는 정해진 간격마다 스스로 일을 시작합니다. 그런데 처음부터 상시 감시를 붙이면, 흐름이 틀렸을 때 틀린 초안이 계속 쌓입니다. 그래서 첫 바퀴는 손으로 돌립니다. 폴더 구조, 파일 이름 규칙, 초안 양식, 결재 대기 자리가 모두 맞는지 확인한 다음에야 방아쇠를 기계에 넘깁니다. 새 직원에게 첫 주는 옆에 앉아 한 건씩 같이 처리하게 하는 것과 같습니다. 일의 순서가 몸에 붙은 뒤에 혼자 맡깁니다.

한 바퀴가 끝나면 폴더 세 개에 파일이 하나씩 남고, 그 자국이 곧 흐름도(3강)의 실물 증거가 됩니다. 트리거를 켤 때도 나누어 맡깁니다. 기계에게는 규칙대로 반복하는 일(새 파일 찾기, 양식 복사, 원본 옮기기, 기록 남기기)만 넘기고, 초안의 내용을 채우는 일과 승인은 계속 사람이 맡습니다.

오늘 새로 쓰는 말 두 가지를 먼저 풀어 둡니다.

- <strong>실행 로그</strong>(실행 기록) — 코드를 한 번 돌릴 때마다 "언제 시작했고, 무엇을 했고, 끝났는지 실패했는지"가 한 줄씩 찍히는 기록입니다. 편집기 아래쪽에 뜹니다.
- <strong>실행 목록</strong> — 편집기 왼쪽 '실행' 화면에 쌓이는, 지금까지 돈 실행들의 목록입니다. 트리거가 사람 없이 돌린 것도 여기에 남습니다.

## 강사의 시스템에서

"켜질 때 한 번 훑는다"는 규칙은 5강에서 보았습니다. 오늘은 그다음, 한 바퀴를 실제로 돌려 보면 설계서에 없던 문제가 드러납니다. 강사의 경우 세 가지였습니다.

1. **글자 깨짐.** 휴대폰 받아쓰기로 만든 텍스트 파일 40건 가운데 34건이 다른 <strong>인코딩</strong>(글자를 컴퓨터 숫자로 바꿔 저장하는 방식 — 방식이 다르면 한글이 깨져 보입니다)으로 저장돼 있어, 초안 뷰어에서 한글이 모두 깨졌습니다. 읽는 함수 한 곳에 "이 형식으로 안 읽히면 다음 형식으로" 순서를 넣어 고쳤습니다.
2. **같은 일이 여러 건으로 쪼개짐.** 어제 넣은 대화와 오늘 받은 추가 자료가 초안 두 건, 결재 두 건으로 갈라졌습니다. 그래서 파일 이름 맨 앞에 `[키]`를 붙이면, 같은 키를 가진 결재 전 초안에 합쳐지도록 규칙을 만들었습니다.
3. **파일 이름이 제목이 됨.** 녹취 파일 이름에 든 상대방 이름과 숫자가 그대로 프로젝트 제목이 될 뻔했습니다. 결론은 초안 맨 위 `제목:` 칸에서만 가져오는 것이었고, 전말은 10강에서 봅니다.

세 문제 모두 코드를 읽어서는 보이지 않았고, 실제 파일로 한 바퀴를 돌렸을 때 보였습니다. 실습을 "눈으로 확인"에서 멈추지 말아야 하는 이유입니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다. 오늘 윤하람 씨는 새봄학습관 담당자 B와 통화한 뒤, 다음 달 후속 강좌 이야기를 남긴 음성 메모를 초안으로 만듭니다. 준비물: 5~7강의 드라이브 `C3_자동화` 폴더, AGY의 `C3_자동화` 프로젝트(6강), 5강의 앱스 스크립트 프로젝트 `인박스감시_v01`.

### 가. 손으로 한 바퀴

1. PC 크롬에서 `https://drive.google.com` → '내 드라이브' → `C3_자동화` 로 들어가 폴더를 확인합니다: `00_inbox`(인박스), `01_draft`(결재 대기), `90_done`(처리가 끝난 원본), `99_error`(처리하다 실패한 원본), `_양식`(초안 양식), `처리기록` 시트, `인박스감시_v01` 스크립트.
2. 같은 자리에서 '+ 새로 만들기' → '새 폴더' → `02_approved` 를 만듭니다. 승인된 초안이 갈 자리입니다. 이름 앞 숫자는 일이 흘러가는 순서입니다.
   → 이렇게 보이면 됩니다: 폴더가 `00_inbox`, `01_draft`, `02_approved`, `90_done`, `99_error` 순서로 늘어서 있습니다.
3. `_양식` → `진행메모_양식` 을 두 번 눌러 열고, 7강에서 고정한 아홉 칸(제목 · 원문 · 한 줄 요약 · 새로 생긴 것 · 부딪히는 것 · 빠진 것 → 물을 것 · 사람이 정할 것 · 할 일 후보 · 처리 기록)이 그대로 있는지 봅니다. 아홉 줄을 복사해 둡니다.
4. 휴대폰으로 통화 직후 1분 동안 메모를 말로 남깁니다. 6강 가의 1~7번과 같은 방법으로 `00_inbox` 안에 구글 문서를 만들고 마이크로 받아씁니다. 상대의 이름·전화번호가 받아쓰기에 섞이면 그 자리에서 "담당자 B"로 고칩니다.
5. PC 크롬 드라이브의 `00_inbox` 에서 그 문서를 두 번 눌러 엽니다. 위쪽 메뉴 '파일' → '다운로드' → '일반 텍스트(.txt)'를 누릅니다.
   → 이렇게 보이면 됩니다: 크롬 오른쪽 위에 다운로드 표시가 뜨고, PC의 '다운로드' 폴더에 `.txt` 파일이 생깁니다. AGY는 `.gdoc` 바로가기를 읽지 못하므로(C0 11강) 이렇게 글 파일로 바꿔 줍니다.
6. `Win + E` 로 파일 탐색기를 열고 왼쪽 '다운로드'를 누릅니다. 방금 받은 `.txt` 파일을 한 번 누르고 `F2` 를 눌러 이름을 `[후속강좌] 260927_담당자통화.txt` 로 바꿉니다. 4강의 규칙(`날짜_내용`) 앞에 같은 일을 묶는 `[키]`를 붙인 것입니다. 사람 이름과 전화번호는 파일 이름에 넣지 않습니다.
7. 이 파일을 마우스로 끌어 탐색기 왼쪽 'Google Drive' → '내 드라이브' → `C3_자동화` → `00_inbox` 위에 놓습니다.
   → 이렇게 보이면 됩니다: `00_inbox` 안에 구글 문서(`.gdoc`)와 `.txt` 파일이 함께 있습니다. 구글 문서는 이제 필요 없으니 `99_error` 가 아닌 `90_done` 으로 옮겨 둡니다(드라이브에서 오른쪽 단추 → '정리' → '이동').
8. AGY에서 `C3_자동화` 프로젝트를 엽니다. 입력칸 근처 모드 단추가 'Planning'(계획 모드)인지 확인하고, 아래 "AI에게 건네는 말"의 첫 번째 글을 보냅니다. `[양식]` 자리에 3번에서 복사한 아홉 줄을 붙입니다.
   → 이렇게 보이면 됩니다: AGY가 계획서를 먼저 보여 줍니다.
   ✖ 계획에 "원본을 지운다"는 단계가 있으면: 'Proceed'를 누르지 않고 "원본은 지우지 말고 90_done으로 옮기기만 해"라고 보냅니다.
9. 계획을 읽고 'Proceed'로 승인합니다. AGY가 `01_draft`에 `[초안] [후속강좌] 260927_담당자통화.md`를 만들고, 초안이 실제로 생긴 것을 확인한 뒤에만 원본 `.txt` 를 `90_done`으로 옮깁니다(5강 규칙). 실패하면 원본은 `99_error`로 갑니다. 어느 경우에도 원본은 지워지지 않습니다.
   → 이렇게 보이면 됩니다: AGY 왼쪽 목록에서 `00_inbox` 가 비고, `01_draft` 에 초안, `90_done` 에 원본이 보입니다.
10. 초안을 눌러 열고 양식 칸이 모두 있는지 봅니다. 내용이 없는 칸은 "없음"이라고 적혀 있어야 합니다. 칸 자체가 없으면 양식 고정이 실패한 것입니다. 맨 위 `제목:` 칸이 본문 첫 줄과 상관없이 한 줄로 따로 있는지도 봅니다.
11. 초안의 사실을 `90_done`의 원본과 대조합니다(두 번째 글). 원본에 없던 날짜·금액·인원이 초안에 있다면, 그것은 AI가 만든 추측입니다. 해당 줄을 "빠진 것 → 물을 것" 칸으로 옮기게 합니다.
12. 같은 키로 추가 메모 한 건을 더 넣습니다. 4~7번을 되풀이해 `[후속강좌] 260928_문자추가요청.txt` 를 `00_inbox` 에 넣고, 첫 번째 글을 다시 보냅니다. 새 초안이 아니라 기존 초안에 합쳐지는지, 합치기 전 판(`_v01` 등)이 남는지 확인합니다.
    ✖ 초안이 두 개로 따로 생겼다면: 파일 이름 맨 앞의 `[후속강좌]` 글자가 두 파일에서 똑같은지(띄어쓰기·괄호 모양까지) 봅니다.
13. 초안 맨 아래에 "처리 기록" 한 줄이 남았는지 봅니다. 예: `0928 14:10 · 원본 2건 반영 · 결재 대기`. 이 줄이 9강 결재판의 재료가 됩니다.
14. 아직 승인하지 않습니다. 초안은 `01_draft`에 둔 채 9강으로 넘어갑니다.
15. 한 바퀴를 돌며 막힌 곳을 설계서(4강) 여백에 적습니다. 예: "받아쓰기 파일이 두 줄씩 띄어져 들어온다", "키를 빼먹으면 초안이 따로 생긴다".

### 나. 트리거를 켜고 사람 없이 한 바퀴

가 부분이 맞게 돌았다면, 이제 반복되는 기계적인 부분을 앱스 스크립트에 넘깁니다. 코드가 할 일은 네 가지뿐입니다: `00_inbox`에서 새 파일 찾기, `_양식/진행메모_양식`을 복사해 `01_draft`에 `[초안] 원본이름` 구글 문서 만들기, 원본 글을 "원문" 칸에 붙이고 끝에 처리 기록 한 줄 남기기, 초안이 실제로 생긴 것을 확인한 뒤에만 원본을 `90_done`으로 옮기기(실패하면 `99_error` 와 `처리기록` 시트). 요약·"빠진 것" 같은 칸을 채우는 일은 여전히 가 부분처럼 사람이 AGY에게 맡깁니다.

**코드 받기** (PC, AGY)

16. AGY의 `C3_자동화` 프로젝트에서 아래 "AI에게 건네는 말" 세 번째 글을 보냅니다. 계획 모드로 먼저 받고, 5강의 세 규칙(새 파일만 · 한 번에 1건씩 · 성공 뒤에 옮기기)이 코드 안에 있는지 설명을 읽고 확인한 뒤에만 승인합니다.
    → 이렇게 보이면 됩니다: AGY가 대화 안에 회색 코드 상자를 보여 주고, 맨 위에 `function checkInbox() {` 같은 줄이 있습니다.
17. 코드 상자 안의 글을 처음부터 끝까지 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다. 상자 오른쪽 위에 복사 모양 아이콘(네모 두 개가 겹친 모양)이 보이면 그것을 눌러도 됩니다.

**편집기에 붙여 넣고 저장하기** (PC, 크롬)

18. 크롬 드라이브의 `C3_자동화` 에서 `인박스감시_v01` 을 두 번 누릅니다(5강에서 만든 프로젝트).
    → 이렇게 보이면 됩니다: 새 탭에 스크립트 편집기가 열리고, 가운데 코드 칸에 `function myFunction() {` 과 `}` 가 보입니다.
19. 코드 칸 안을 한 번 누르고 `Ctrl + A` 로 기존 두 줄을 모두 선택한 뒤 `Ctrl + V` 로 붙여 넣습니다. 기존 두 줄은 붙여 넣은 코드로 바뀝니다.
    → 이렇게 보이면 됩니다: 코드 칸에 수십 줄이 색깔 있는 글자로 채워지고, 왼쪽에 줄 번호가 붙습니다.
20. `Ctrl + S` 를 누르거나 위쪽 도구 줄의 '프로젝트 저장'(디스크 모양)을 누릅니다.
    → 이렇게 보이면 됩니다: 저장이 끝나면 위쪽 함수 선택 칸의 글자가 `myFunction` 에서 코드 속 함수 이름(`checkInbox` 등)으로 바뀝니다.
    ✖ 저장할 때 빨간 줄과 함께 "구문 오류" 같은 알림이 뜨면: 코드 일부가 복사되지 않은 것입니다. 19번부터 다시 하되, 17번에서 코드 상자 맨 끝 `}` 까지 빠짐없이 선택합니다.
21. 프로젝트 이름을 4강 규칙대로 바꿔 둡니다. 왼쪽 위 `인박스감시_v01` 을 누르고 `260928_인박스감시_v01` 로 고친 뒤 '이름 바꾸기'를 누릅니다.

**손으로 한 번 실행하고 권한 승인하기**

22. 위쪽 도구 줄의 함수 선택 칸(지금 함수 이름이 적힌 칸)을 누르고, 목록에서 `checkInbox` 를 누릅니다. 목록에 함수가 여러 개 보여도, AGY가 "트리거가 부를 함수"라고 말한 것 하나만 고릅니다.
23. 연습용으로 `00_inbox` 를 비운 뒤 파일 1건만 넣습니다. 6강에서 만든 문서 등이 남아 있으면 먼저 드라이브에서 오른쪽 단추 → '정리' → '이동'으로 `90_done` 에 옮깁니다. 그다음 휴대폰이나 PC에서 6강 가 방법으로 짧은 구글 문서 하나를 만들고 이름을 `[연습] 260928_짧은메모` 로 붙입니다.
24. 편집기로 돌아와 도구 줄의 '실행'(▷)을 누릅니다.
    → 이렇게 보이면 됩니다: 처음 실행이라 '승인 필요'라는 작은 창이 뜨고, "이 프로젝트가 내 데이터에 액세스하려면 권한이 필요하다"는 뜻의 글과 '권한 검토' 버튼이 보입니다.
25. '권한 검토'를 누릅니다. 새 창에 구글 계정 목록이 뜨면, 드라이브에 `C3_자동화` 가 있는 내 계정을 누릅니다.

## AI에게 건네는 말

> **어디에 입력하나요:** 바탕화면이나 시작 메뉴에서 'Antigravity'를 눌러 AGY를 엽니다. 작업 폴더가 열려 있는지 먼저 봅니다(C1 3강). 화면 아래쪽의 채팅 입력칸(에이전트에게 말을 거는 칸)을 누르고, 아래 글을 붙여 넣은 뒤 `Enter` 로 보냅니다. AGY가 대화 안에 계획이나 확인 카드를 먼저 보여 주면, 바로 승인하지 말고 무엇을 하겠다는지 읽은 뒤 결정합니다(C1 9강).

오늘의 작업 폴더는 6강에서 만든 `C3_자동화` 프로젝트입니다.

첫 번째 글 (8번, 12번):

> 00_inbox 폴더의 .txt 파일을 한 건씩 처리해, 01_draft 폴더에 아래 [양식]의 칸 이름과 순서 그대로 초안을 .md 파일로 만들어 줘. 파일 이름 맨 앞 [키]가 같은 초안이 01_draft에 이미 있으면 새로 만들지 말고 거기에 합치고, 합치기 전 내용은 _v01처럼 판 번호를 붙인 파일로 남겨 줘. 초안이 실제로 생긴 것을 확인한 뒤에만 원본을 90_done으로 옮기고, 실패하면 99_error로 옮겨. 원본은 지우지 마. '제목:' 칸은 파일 이름이 아니라 내용에서 한 줄로 따로 써 줘. 원본에 없는 날짜·금액·인원은 쓰지 말고 '빠진 것 → 물을 것' 칸에 질문으로 적어 줘. 맨 끝 '처리 기록' 칸에 시각 · 반영한 원본 수 · 결재 대기를 한 줄로 적어 줘. 실행 전에 계획부터 보여 줘.
> [양식]

답을 읽는 법: 계획서에서 "만들 파일"이 `01_draft` 의 초안 하나(합치는 경우 판 번호 파일 하나 더)이고, "옮길 파일"이 원본 하나이며, "지울 파일"이 없는지 봅니다.

두 번째 글 (11번):

> 방금 만든 초안과 90_done의 원본을 나란히 놓고, 초안에만 있고 원본에는 없는 사실을 표로 뽑아 줘. 열은 '초안 문장 / 원본 근거 유무 / 처리 제안'으로 해 줘. 파일은 아직 고치지 마.

답을 읽는 법: '원본 근거 유무'가 "없음"인 줄마다 "그 줄을 '빠진 것 → 물을 것'으로 옮겨 줘"라고 보냅니다.

세 번째 글 (16번):

> 5강에서 세운 계획대로 구글 앱스 스크립트 코드를 써 줘. 폴더는 모두 내 드라이브의 C3_자동화 폴더 안에 있고, 이름으로 찾되 같은 이름이 둘 이상이면 멈추고 알려 줘. 트리거가 부를 함수 이름은 checkInbox 로 하고, 이 함수는 00_inbox 폴더에서 이름이 TEST_로 시작하지 않는 새 파일을 한 번에 1건만 처리한다. 원본이 구글 문서면 본문 글을, .txt 파일이면 한글이 깨지지 않게 파일 내용을 읽는다. _양식/진행메모_양식 문서를 복사해 01_draft 폴더에 "[초안] 원본 파일 이름" 구글 문서로 만들고, 원본 글은 "원문:" 칸 아래에, 맨 끝에 "처리 기록: 날짜 시각 · 원본 1건 반영 · 결재 대기" 한 줄을 넣는다. 초안 문서가 실제로 생긴 것을 확인한 뒤에만 원본을 90_done으로 옮기고, 실패하면 원본을 99_error로 옮기고 처리기록 시트에 시각·파일 이름·결과·오류 내용을 한 줄 적은 뒤 멈춘다. 원본은 절대 지우지 않는다. 요약이나 판단이 필요한 칸은 채우지 말고 "없음"으로 둔다. 실행 로그에서 읽을 수 있게, 단계마다 한국어로 짧은 기록(예: "처리 시작: 파일 이름", "처리할 파일 없음")을 남겨 줘. 코드는 파일로 만들지 말고 대화 안에 코드 상자 하나로 보여 줘. 코드를 쓰기 전에 이 규칙이 각각 몇 번째 줄에서 지켜지는지 설명해 줘. 나는 앱스 스크립트 편집기에 붙여 넣어 직접 실행할 것이다.

답을 읽는 법: 설명에서 "원본을 옮기는 줄"의 번호가 "초안이 생긴 것을 확인하는 줄"의 번호보다 큰지 봅니다. 작다면 순서가 뒤집힌 것이니 승인하지 않고 고쳐 달라고 합니다. 코드 안에 "삭제", `setTrashed`, `remove` 같은 말이 보이면 "이 줄은 무엇을 지우는 거야?"라고 묻습니다.

## 손에 남길 것과 완료 확인

**한 바퀴 돈 흔적: 흐름 폴더와 초안 2건 이상(손으로 1건, 트리거로 1건)**

- [ ] `00_inbox` · `01_draft` · `02_approved` · `90_done` · `99_error` · `_양식` 폴더가 있다
- [ ] 원본 파일이 지워지지 않고 `90_done`(실패했다면 `99_error`)에 있다
- [ ] 초안이 7강 양식의 칸을 모두 갖췄고, 빈 칸은 "없음"으로 적혀 있다
- [ ] 초안 맨 위 `제목:` 칸이 한 줄로 따로 있고, 사람 이름·번호가 없다
- [ ] 원본에 없는 사실이 초안에 남아 있지 않다(있다면 "빠진 것 → 물을 것"으로 옮겼다)
- [ ] 같은 키의 두 번째 자료가 기존 초안에 합쳐졌고, 합치기 전 판이 남아 있다
- [ ] 파일 이름에 사람 이름·전화번호가 없다
- [ ] 초안 끝에 처리 기록 한 줄이 있다
- [ ] 막힌 곳이 설계서에 한 줄 이상 적혀 있다
- [ ] 앱스 스크립트 코드의 세 규칙(새 파일만 · 1건씩 · 성공 뒤에 옮기기)을 내가 읽고 확인했다
- [ ] 손으로 한 번 실행해 권한 승인을 마쳤고, 실행 로그에서 "실행이 완료됨"을 보았다
