# 8강. 실습 ② 인박스에서 초안까지 한 바퀴

유정근 · 마이웨이 아카데미 | C3 업무 자동화

척추: 12블럭 B10

## 오늘의 목표

드라이브의 인박스 폴더에 메모 한 건을 넣고, AGY가 7강의 고정 양식으로 초안을 만들어 "결재 대기" 폴더에 놓기까지 한 바퀴를 직접 돌립니다. 오늘은 사람이 방아쇠를 당기는 자동화입니다. 감시가 아니라 "지금 인박스를 처리해 줘"라는 한 마디가 시작 신호입니다.

## 먼저 이해하기

5강에서 설계한 감시 자동화는 정해진 간격마다 스스로 일을 시작합니다. 그런데 처음부터 상시 감시를 붙이면, 흐름이 틀렸을 때 틀린 초안이 계속 쌓입니다. 그래서 첫 바퀴는 손으로 돌립니다. 폴더 구조, 파일 이름 규칙, 초안 양식, 결재 대기 자리가 모두 맞는지 확인한 다음에야 방아쇠를 기계에 넘깁니다. 이는 새 직원에게 첫 주는 옆에 앉아 한 건씩 같이 처리하게 하는 것과 같습니다. 일의 순서가 몸에 붙은 뒤에 혼자 맡깁니다. 한 바퀴가 끝나면 폴더 세 개에 파일이 하나씩 남고, 그 자국이 곧 흐름도(3강)의 실물 증거가 됩니다.

## 강사의 시스템에서

"켜질 때 한 번 훑는다"는 규칙은 5강에서 보았습니다. 오늘은 그다음, 한 바퀴를 실제로 돌려 보면 설계서에 없던 문제가 드러납니다. 강사의 경우 세 가지였습니다.

1. **글자 깨짐.** 휴대폰 받아쓰기로 만든 텍스트 파일 40건 가운데 34건이 다른 인코딩으로 저장돼 있어, 초안 뷰어에서 한글이 모두 깨졌습니다. 읽는 함수 한 곳에 "이 형식으로 안 읽히면 다음 형식으로" 순서를 넣어 고쳤습니다.
2. **같은 일이 여러 건으로 쪼개짐.** 어제 넣은 대화와 오늘 받은 추가 자료가 초안 두 건, 결재 두 건으로 갈라졌습니다. 그래서 파일 이름 맨 앞에 `[키]`를 붙이면, 같은 키를 가진 결재 전 초안에 합쳐지도록 규칙을 만들었습니다.
3. **파일 이름이 제목이 됨.** 녹취 파일 이름에 든 상대방 이름과 숫자가 그대로 프로젝트 제목이 될 뻔했습니다. 결론은 초안 맨 위 `제목:` 칸에서만 가져오는 것이었고, 전말은 10강에서 봅니다.

세 문제 모두 코드를 읽어서는 보이지 않았고, 실제 파일로 한 바퀴를 돌렸을 때 보였습니다. 실습을 "눈으로 확인"에서 멈추지 말아야 하는 이유입니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다. 오늘 윤하람 씨는 새봄학습관 담당자 B와 통화한 뒤, 다음 달 후속 강좌 이야기를 남긴 음성 메모를 초안으로 만듭니다.

1. 5강과 7강에서 만든 폴더를 확인합니다. `00_inbox`(인박스), `01_draft`(결재 대기), `90_done`(처리가 끝난 원본), `99_error`(처리하다 실패한 원본), `_양식`(초안 양식). 여기에 승인된 초안이 갈 `02_approved`를 하나 더 만듭니다. 이름 앞 숫자는 일이 흘러가는 순서입니다.
2. `_양식` 폴더의 `진행메모_양식`을 엽니다. 7강에서 고정한 칸(제목 · 원문 · 한 줄 요약 · 새로 생긴 것 · 부딪히는 것 · 빠진 것 → 물을 것 · 사람이 정할 것 · 할 일 후보 · 처리 기록)이 그대로 있는지 확인합니다.
3. 휴대폰으로 통화 직후 1분 음성 메모를 남기고, 받아쓰기로 텍스트를 만듭니다(6강). 녹음 원본에 상대의 개인정보가 섞여 있다면 텍스트에서 먼저 지웁니다.
4. 텍스트를 `00_inbox`에 넣습니다. 파일 이름은 4강의 규칙(`날짜_내용`) 앞에 같은 일을 묶는 `[키]`를 붙입니다. 예: `[후속강좌] 260927_담당자통화.txt`. 사람 이름과 전화번호는 파일 이름에 넣지 않습니다. 6강처럼 구글 문서로 받아썼다면, C0에서 본 대로 내 컴퓨터의 `.gdoc`은 내용이 없는 바로가기라 AGY가 읽지 못합니다. 문서 메뉴의 다운로드에서 일반 텍스트(.txt)로 저장해 넣습니다.
5. AGY를 흐름용 폴더가 보이는 작업 폴더에서 열고, 계획 모드로 아래 "AI에게 건네는 말" 첫 번째 요청을 보냅니다(C1). 계획에 "원본을 옮기거나 지운다"는 단계가 있으면 승인하지 말고 고쳐 달라고 합니다.
6. 계획을 승인하면 AGY가 `01_draft`에 `[초안] [후속강좌] 260927_담당자통화.md`를 만들고, 초안이 실제로 생긴 것을 확인한 뒤에만 원본을 `90_done`으로 옮깁니다(5강 규칙). 실패하면 원본은 `99_error`로 갑니다. 어느 경우에도 원본은 지워지지 않습니다.
7. 초안을 열어 양식 칸이 모두 있는지 봅니다. 내용이 없는 칸은 "없음"이라고 적혀 있어야 합니다. 칸 자체가 없으면 양식 고정이 실패한 것입니다. 맨 위 `제목:` 칸이 본문 첫 줄과 상관없이 한 줄로 따로 있는지도 봅니다. 이 제목이 10강에서 산출물의 이름이 됩니다.
8. 초안의 사실을 `90_done`의 원본과 대조합니다. 원본에 없던 날짜·금액·인원이 초안에 있다면, 그것은 AI가 만든 추측입니다. 해당 줄을 "빠진 것 → 물을 것" 칸으로 옮깁니다.
9. 같은 키로 추가 메모 한 건을 더 넣습니다. 예: `[후속강좌] 260928_문자추가요청.txt`. 두 번째 요청을 보내 새 초안이 아니라 기존 초안에 합쳐지는지, 합치기 전 버전이 남는지 확인합니다.
10. 초안 맨 아래에 "처리 기록" 한 줄이 남았는지 봅니다. 예: `0928 14:10 · 원본 2건 반영 · 결재 대기`. 이 줄이 9강 결재판의 재료가 됩니다.
11. 아직 승인하지 않습니다. 초안은 `01_draft`에 둔 채 9강으로 넘어갑니다.
12. 한 바퀴를 돌며 막힌 곳을 설계서(4강) 여백에 적습니다. 예: "받아쓰기 파일이 두 줄씩 띄어져 들어온다", "키를 빼먹으면 초안이 따로 생긴다".

## AI에게 건네는 말

> 00_inbox 폴더의 파일을 한 건씩 처리해, 01_draft 폴더에 _양식/진행메모_양식의 칸 이름과 순서 그대로 초안을 만들어 줘. 파일 이름 맨 앞 [키]가 같은 초안이 01_draft에 이미 있으면 새로 만들지 말고 거기에 합치고, 합치기 전 내용은 버전으로 남겨 줘. 초안이 실제로 생긴 것을 확인한 뒤에만 원본을 90_done으로 옮기고, 실패하면 99_error로 옮겨. 원본은 지우지 마. '제목:' 칸은 파일 이름이 아니라 내용에서 한 줄로 따로 써 줘. 원본에 없는 날짜·금액·인원은 쓰지 말고 '빠진 것 → 물을 것' 칸에 질문으로 적어 줘. 실행 전에 계획부터 보여 줘.

> 방금 만든 초안과 원본을 나란히 놓고, 초안에만 있고 원본에는 없는 사실을 표로 뽑아 줘. 열은 '초안 문장 / 원본 근거 유무 / 처리 제안'으로 해 줘.

## 손에 남길 것과 완료 확인

**한 바퀴 돈 흔적: 흐름 폴더와 초안 1건**

- [ ] `00_inbox` · `01_draft` · `02_approved` · `90_done` · `99_error` · `_양식` 폴더가 있다
- [ ] 원본 파일이 지워지지 않고 `90_done`(실패했다면 `99_error`)에 있다
- [ ] 초안이 7강 양식의 칸을 모두 갖췄고, 빈 칸은 "없음"으로 적혀 있다
- [ ] 초안 맨 위 `제목:` 칸이 한 줄로 따로 있고, 사람 이름·번호가 없다
- [ ] 원본에 없는 사실이 초안에 남아 있지 않다(있다면 "빠진 것 → 물을 것"으로 옮겼다)
- [ ] 같은 키의 두 번째 자료가 기존 초안에 합쳐졌고, 합치기 전 버전이 남아 있다
- [ ] 파일 이름에 사람 이름·전화번호가 없다
- [ ] 초안 끝에 처리 기록 한 줄이 있다
- [ ] 막힌 곳이 설계서에 한 줄 이상 적혀 있다

모두 체크되면 완료입니다. 승인은 다음 강에서 합니다.
