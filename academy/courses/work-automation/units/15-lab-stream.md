# 15강. 실습 ③ 나의 줄기 문서 한 장과 원장 첫 줄

유정근 · 마이웨이 아카데미 | C3 업무 자동화
척추: 12블럭 B10

## 오늘의 목표

내 일 가운데 가장 오래 이어질 줄기 하나를 골라 **줄기 문서 한 장** (헌장 · 가지와 건 · 단계표 · 결정 · 충돌 대기 · 정책)을 쓰고, 덧붙이기만 하는 <strong>원장 시트</strong>에 첫 줄을 남깁니다. 그리고 AI가 초안을 쓰기 전에 이 두 문서를 먼저 읽게 만드는 요청문을 완성합니다.

## 먼저 이해하기

13강은 원장의 개념을, 14강은 단계표를 다뤘습니다. 오늘은 둘을 실제 문서로 세웁니다. 줄기 문서는 "지금 상태의 요약"이고, 원장은 "무슨 일이 있었는지의 증거"입니다. 요약은 고쳐 쓰지만, 원장은 지우거나 고치지 않고 아래에 한 줄씩 더하기만 합니다. 요약이 틀어지면 원장에서 다시 만들 수 있기 때문입니다.

비유하자면 배의 해도와 항해일지입니다. 해도(줄기 문서)에는 지금 배가 어디 있는지 연필로 표시하고, 위치가 바뀌면 지우고 다시 찍습니다. 항해일지(원장)에는 몇 시에 무엇을 보았고 무엇을 결정했는지를 잉크로 한 줄씩 적습니다. 해도의 표시가 의심스러우면 항해일지를 거슬러 읽어 위치를 다시 계산합니다. 항해일지를 지우고 고쳐 쓰는 선장은 없습니다.

오늘 만드는 문서는 둘 다 **비공개 폴더** 에만 둡니다. 사람 이름과 약속이 들어가기 때문입니다. 공개와 비공개의 원칙은 C2 19강에서 배운 그대로입니다.

## 강사의 시스템에서

강사의 수로는 줄기 하나에 파일 두 개로 시작했습니다. 줄기 문서 하나와 원장 하나. 가지를 파일로 쪼개지 않고 줄기 문서 안의 섹션으로 두었는데, 그래야 헌장과 가지를 AI가 한 번에 읽기 때문입니다. 첫 개설은 사람 손으로 약 40분을 잡았습니다. 코드는 한 줄도 바뀌지 않았고, 이 단계를 "수동 개시"라고 불렀습니다. 자동화는 그다음이었습니다.

줄기 문서 맨 아래에는 정책 네 줄이 있습니다.

```
auto_draft: true        # 초안 자동 생성
auto_plan: true         # 산출물 기획까지 자동
auto_send: false        # 대외 발송은 항상 사람
needs_human: [강의료, 일정 확정, 계약, 이력서·개인정보]
```

이 네 줄이 자동화의 경계선입니다. 초안과 기획은 AI가 앞서 가도 되지만, 대외 발송과 돈·날짜·계약·개인정보는 어느 단계에서도 자동으로 넘지 않습니다. 19강에서 이 정책을 더 넓게 다룹니다.

원장 한 줄은 이런 모양입니다(가상 값).

```
{"ts":"2026-10-02T14:02","src":"음성메모_1002.m4a","people":["담당자A"],"case":"신입 보고서 과정","summary":"회차 수 문의","decisions":[],"todos":["예산 범위 질의"]}
```

그리고 경계가 하나 있습니다. 사람 카드에는 상담 원문이나 개인정보를 옮기지 않고, 필요하면 "어디에 있는지"만 적습니다. 원장은 공개 포털이나 공개 저장소로 가는 동기화 대상에 넣지 않습니다. 강사는 이 경계를 설계 문서의 첫머리에 적어 두었습니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다. 내 일을 쓰기 어렵다면 윤하람 씨의 "강의 의뢰" 줄기로 같은 절차를 밟습니다.

1. **줄기를 고릅니다.** 앞으로 석 달 이상 이어질 일 하나입니다. 기준은 "같은 사람·같은 목적의 연락이 두 번 이상 왔거나 올 것"입니다.
2. **폴더를 만듭니다.** 드라이브의 비공개 영역에 `_줄기` 폴더를 만들고, 그 안에 줄기 이름의 폴더를 하나 더 만듭니다. 예) `_줄기/강의의뢰`. 공유 설정이 "나만"인지 확인하고, 14강의 `단계표_강의의뢰` 시트를 이 폴더로 옮깁니다. 이름 앞의 `_`는 `_양식`처럼 흐름 밖에서 참고하는 폴더라는 표시입니다.
3. **줄기 문서를 만듭니다.** 구글 문서 `stream_강의의뢰`를 만들고 제목 여섯 개를 넣습니다: 헌장 / 가지와 건 / 단계표 / 결정 사항 / 충돌 대기 / 정책.
4. **헌장을 네 줄로 씁니다.** 나의 역할, 영역, 관여자(역할로만 적어도 됩니다), 공통 원칙. 예) "공통 원칙: 실습 비중 절반 이상, 참가자 실제 문서는 받지 않고 가상 문서로 연습".
5. **가지와 건을 적습니다.** 가지는 대상, 건은 기관별 실제 과정입니다. 건마다 세 줄만: 현재 단계 / 근거(날짜·출처) / 빠진 완료 조건.
6. **단계표를 붙입니다.** 14강에서 만든 시트의 링크를 넣거나 표를 옮겨 붙입니다. 둘 중 한 곳만 정본으로 정하고, 다른 곳에는 "정본은 저기"라고 적습니다.
7. **결정 사항과 충돌 대기를 비워 둡니다.** 칸만 만들어 둡니다. 결정은 "날짜 · 출처 · 누가"를 함께 적는 곳이고, 충돌 대기는 서로 다른 말이 부딪혀 사람 판단을 기다리는 곳이라는 설명 한 줄만 씁니다.
8. **정책 네 줄을 씁니다.** 초안 자동 / 기획 자동 / 대외 발송은 사람 / 사람만 판단할 것 목록. 하람 씨는 `needs_human: [강의료, 일정 확정, 계약, 참가자 개인정보]`로 적었습니다.
9. **사람 카드를 한 장 만듭니다.** 같은 폴더에 `사람_담당자A` 문서를 만들고 소속 · 관계 · 관여 줄기 · 소통 선호 · 열린 약속 · 금지 영역을 적습니다. 상담 내용이나 연락처는 옮기지 않습니다. 13강에서 초안을 써 본 `사람_담당자B`가 있다면 함께 둡니다.
10. **원장 시트를 만듭니다.** 구글 시트 `ledger_강의의뢰`에 칸을 만듭니다: 시각 / 출처 / 사람 / 건 / 요약 / 결정 / 할 일 / 단계 변화(예: `제안→확정`, 없으면 비움). 첫 행은 칸 이름입니다.
11. **원장 첫 줄을 남깁니다.** 최근 자료 하나(메모·메일·녹음 요약)를 골라 한 줄을 채웁니다. 지금까지의 사정을 알려 주는 "개설" 줄이어도 좋습니다. 이 시트의 규칙을 첫 탭 맨 위 메모에 적습니다: "고치지 않는다. 틀렸으면 아래에 정정 줄을 더한다."
12. **AI에게 먼저 읽히기.** 아래 첫 번째 요청문으로 새 자료 하나를 처리해 보고, 초안 맨 위에 건 · 단계 판정 · 빠진 완료 조건이 나왔는지 확인합니다. 나오지 않았다면 요청문을 고칩니다.

## AI에게 건네는 말

> 초안을 쓰기 전에 이 세 문서를 먼저 읽어 줘: 줄기 문서 `stream_강의의뢰`, 사람 카드 `사람_담당자A`, 원장 `ledger_강의의뢰`의 마지막 5줄. 그다음 새 자료(붙여 넣기)를 처리해. 초안 맨 위에는 반드시 네 칸을 먼저 써 줘: ① 해당 건 ② 단계 판정(유지 또는 `단계 제안: 현재 → 다음`) ③ 이번에 새로 생긴 것 ④ 기존 결정과 부딪히는 것. 부딪히는 것은 판정하지 말고 드러내기만 해. 정책의 `needs_human`에 걸리는 내용은 결정처럼 쓰지 말고 "사람 확인 필요"로 표시해.

> 이 줄기 문서와 사람 카드를 읽고, 공개되면 안 되는 정보(실명·연락처·금액·상담 내용)가 들어간 줄을 찾아 줘. 지우지는 말고 줄 위치만 알려 줘.

## 손에 남길 것과 완료 확인

**비공개 폴더 안의 줄기 문서 1장 · 사람 카드 1장 · 원장 시트(첫 줄 포함) · 먼저 읽히는 요청문 1개**

- [ ] 줄기 폴더의 공유 설정이 "나만"이다
- [ ] 줄기 문서에 헌장 · 가지와 건 · 단계표 · 결정 사항 · 충돌 대기 · 정책의 여섯 제목이 있다
- [ ] 건마다 현재 단계 · 근거 · 빠진 완료 조건 세 줄이 있다
- [ ] 단계표의 정본이 한 곳으로 정해져 있다
- [ ] 정책에 "대외 발송은 사람"과 `needs_human` 목록이 있다
- [ ] 사람 카드에 상담 원문·연락처를 옮기지 않았다
- [ ] 원장 시트에 첫 줄이 있고, "고치지 않고 더한다" 규칙이 적혀 있다
- [ ] AI 초안 맨 위에 건 · 단계 판정 · 새로 생긴 것 · 부딪히는 것이 나왔다
- [ ] 단계 변경은 내가 승인한 뒤에만 원장에 적었다

원장이 한 줄뿐이어도 괜찮습니다. 두 번째 자료가 들어왔을 때 AI가 첫 줄을 기억하고 쓰는지, 그 차이를 확인하는 것이 이 실습의 진짜 결과입니다.
