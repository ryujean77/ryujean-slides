# 17강. 내 컴퓨터에서 돌릴까, 서버에서 돌릴까 — 로컬·클라우드 에이전트

유정근 · 마이웨이 아카데미 | C3 업무 자동화
척추: 12블럭 B12

## 오늘의 목표

내 자동화 하나를 두고 "내 컴퓨터에서 돌릴 것인가, 내가 없어도 도는 곳에서 돌릴 것인가"를 다섯 가지 물음으로 판정합니다. 그리고 어느 쪽이든 반드시 붙여야 할 **한도 · 정지선 · 끄는 법** 세 줄을 적습니다.

## 먼저 이해하기

오늘 나오는 말을 먼저 풀어 둡니다.

- **로컬**: 내 컴퓨터 안을 말합니다. 로컬 에이전트는 내 컴퓨터에서 도는 AI 조수입니다. 이 과정의 AGY가 여기에 해당합니다.
- **서버**: 인터넷 너머에서 늘 켜져 있는 남의 컴퓨터입니다. 내가 컴퓨터를 꺼도 서버는 계속 돕니다.
- **클라우드**: 이런 서버를 빌려 쓰는 방식입니다. 클라우드 에이전트는 서버에서 도는 AI 조수입니다. 12강의 앱스 스크립트 트리거도 구글의 서버에서 돕니다.
- **한도**: 한 번에, 또는 하루에 얼마까지만 하도록 정해 둔 상한입니다. 예: "메일 1통", "하루 호출 10회".
- **정지선**: 무엇이 되면 스스로 멈추는지 정해 둔 선입니다. 예: "실패가 두 번 연속이면 멈춘다".
- **끄는 법**: 급할 때 자동화를 완전히 멈추는 절차입니다.

지금까지 AGY와 함께 한 일은 대부분 <strong>내 컴퓨터(로컬)</strong>에서 일어났습니다. 내가 앉아 있고, AGY가 띄우는 확인 카드(일하기 전에 허락을 받으려고 대화 안에 띄우는 작은 카드)에 답하고, 결과를 바로 엽니다. 반면 12강의 앱스 스크립트 트리거는 <strong>구글의 서버(클라우드)</strong>에서 돕니다. 공식 문서의 표현대로 시간 기반 트리거가 돌 때 "당신은 컴퓨터 앞에 있지 않을 수도" 있습니다.

둘은 우열이 아니라 성격이 다릅니다. 로컬은 자료가 밖으로 나가지 않고 사람이 곁에 있지만, 컴퓨터가 꺼지면 멈춥니다. 클라우드는 내가 자는 동안에도 돌지만, 무엇이 언제 얼마나 돌았는지 내 눈에 보이지 않습니다. 그래서 클라우드로 갈수록 <strong>스스로 멈추는 장치</strong>가 더 많이 필요합니다.

비유하자면 집 부엌과 임대 주방입니다. 집 부엌은 내가 있을 때만 불이 켜지고, 재료가 집 밖으로 나가지 않습니다. 임대 주방은 내가 자는 동안에도 불을 켜 둘 수 있지만, 월세는 불을 꺼도 나갑니다. 그리고 마지막에 불을 끄고 문을 잠그는 사람을 미리 정해 두지 않으면, 아무도 잠그지 않습니다.

판정 물음은 다섯 가지입니다.

| 물음 | 로컬 쪽으로 | 클라우드 쪽으로 |
|---|---|---|
| 내가 자리에 없어도 돌아야 하나? | 아니오 | 예 |
| 입력 자료가 어디 있나? | 내 컴퓨터 | 드라이브·시트·메일 |
| 밖에 나가면 안 되는 자료인가? | 예 | 아니오, 또는 정제 후 |
| 확인 카드나 권한 승인에 답할 사람이 있나? | 있다 | 없다 → 권한을 미리 좁게 정해 둔다 |
| 누가, 어떻게 끄나? | 창을 닫는다 | 트리거 삭제·서버 종료 절차가 따로 있다 |

## 강사의 시스템에서

강사는 같은 목적(문서 초안을 만드는 작은 서비스)을 로컬과 클라우드 두 가지로 모두 지어 보았습니다.

**로컬 작업실.** 내 컴퓨터에 설치한 무료 언어 모델(글을 읽고 쓰는 AI의 본체 프로그램)로 "작업 입력 → 계획 → 초안 → 자체 검토 → 문서 저장"을 돌리는 실행기입니다. 외부 사용료는 0원이지만 전력과 하드웨어 비용은 든다고 문서에 적었습니다. 이 실행기에 붙은 한도가 눈여겨볼 만합니다.

- 대기열(처리를 기다리는 작업 줄)은 최대 5건, 한 번에 한 건씩 처리합니다. 등록된 작업이 없으면 모델을 부르지 않습니다.
- 작업당 모델 호출(AI에게 일을 한 번 시키는 것)은 최대 3회, 단계마다 출력 길이 상한과 응답 대기 제한(호출당 240초)이 있습니다.
- 한도에 닿거나 오류가 나면 **완료로 표시하지 않고,** 실패한 작업을 끝없이 다시 시도하지 않습니다.
- 도중에 꺼졌던 작업은 다시 켰을 때 '중단됨'으로 표시될 뿐, 저절로 다시 돌지 않습니다.
- 화면은 이 컴퓨터 안에서만 열리도록 묶어 두었고, 모델이 만든 글 속의 코드나 파일 경로는 실행하지 않습니다.

그리고 첫 실행에서 중요한 교훈이 나왔습니다. 파일은 잘 만들어졌는데, 검수해 보니 실제 인물의 이름이 섞여 들어갔고 아직 정해지지 않은 제안을 결정된 것처럼 써 놓았습니다. 결과는 '검토 필요'로 보류되었습니다. **생성 성공은 내용 검증 통과가 아닙니다.**

**클라우드 에이전트.** 월 6달러짜리 가장 작은 임대 서버에 초안 생성기를 올렸습니다. 하루로 치면 약 280원입니다. 여기에는 로컬에는 없던 장치들이 붙었습니다.

- **예산 장부.** 모델을 부르기 전에 비용을 먼저 예약하고, 부른 뒤에 정산합니다. 하루 호출 횟수에도 상한이 있습니다.
- **정지선.** 누적 서버비가 미리 정한 금액(실험 예산 5만 원의 절반)에 닿으면 생산을 멈추고, 일일 보고 맨 위에 "직접 서버를 삭제하라"는 절차를 띄웁니다. 이 프로그램에는 과금을 스스로 끊을 권한이 없었고, 보고서는 그 사실을 숨기지 않고 적습니다. 에이전트를 멈춰도 서버 요금은 멈추지 않습니다. 임대 주방의 월세입니다.
- **예약 실행.** 매일 새벽 한 번 도는 타이머(정해진 시각에 프로그램을 깨우는 설정)를 달았습니다. 놀랍게도 이 장치가 생기기 전의 진단 기록은 이랬습니다. 코드 530줄 가운데 스스로 돌게 하는 코드는 0줄, 서버에 등록된 타이머 0개. 막힐 때마다 에이전트는 코드를 쓰지 않고 문서를 한 편 더 썼습니다. "됐다/안 됐다"를 코드로 판정하는 기준이 없었기 때문입니다.

클라우드에서만 드러난 실패도 세 가지 있었습니다.

1. **무료 모델이 도중에 유료로 바뀌었습니다.** 몇 분 전까지 답하던 모델이 "무료로 쓸 수 없다"는 응답을 돌려주었습니다. 다음 모델로 넘어가는 대체 경로(첫 길이 막히면 쓰는 두 번째 길)를 붙였습니다. 무료 위에 세운 자동화는 예고 없이 바닥이 빠질 수 있습니다.
2. **점검이 실제 일과 한도를 다투었습니다.** 매일 도는 자가 점검이 실제 주문과 같은 하루 호출 한도를 썼고, 한도가 찬 날 보고서는 이를 "실패"라고 불렀습니다. 바쁜 날일수록 거짓 경보가 울리는 구조였습니다. 점검은 실제 일 뒤에 서도록, 건너뛴 것은 실패로 보고하지 않도록 고쳤습니다.
3. **로컬 시험은 모두 통과했는데 서버에서 죽었습니다.** 함수(코드 안의 이름 붙은 일 묶음) 이름을 바꾸면서 진입점(서버가 프로그램을 시작할 때 가장 먼저 부르는 곳)의 호출 한 곳을 놓쳤고, 시험은 함수를 직접 불렀을 뿐 서버가 실제로 실행하는 진입점을 확인하지 않았습니다. 진입점 시험을 추가했습니다.

강사는 두 경험을 이렇게 정리했습니다. 로컬은 "내가 곁에 있는 자동화", 클라우드는 "내가 없을 때를 위한 자동화"입니다. 곁에 없을 것이라면 한도와 정지선과 끄는 법이 코드 안에 있어야 합니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다. 수강생 실습에서는 서버를 빌리지 않습니다. 클라우드 쪽은 앱스 스크립트의 시간 기반 트리거로 충분합니다. PC의 크롬에서 합니다.

### 가. 판정표 만들기

1. 윤하람 씨는 자동화 두 개를 판정하기로 했습니다. (가) 음성 메모를 진행 메모 초안으로 바꾸기, (나) 매주 월요일 아침 신청 현황 요약 메일을 나에게 보내기.
2. 크롬에서 `https://docs.google.com` 을 열고 '빈 문서'를 눌러 새 문서를 만듭니다. 제목을 `자동화판정표` 로 적습니다.
3. 위쪽 메뉴 '삽입' → '표'를 누르고, 칸 모양이 나오면 마우스를 옮겨 가로 3칸 × 세로 6칸을 고릅니다. 첫 줄에 `물음 / (가) 음성 메모 초안 / (나) 월요일 요약 메일` 을 적고, 아래 다섯 줄에 위의 판정 물음 다섯 개를 한 칸에 하나씩 적습니다.
4. (가)의 칸을 채웁니다. 녹음 원문이 휴대폰과 내 컴퓨터에 있고, 결과를 바로 읽고 고쳐야 합니다. 판정: 로컬(AGY).
5. (나)의 칸을 채웁니다. 하람 씨가 월요일 아침에 컴퓨터 앞에 없어도 와야 합니다. 판정: 클라우드(앱스 스크립트 시간 기반 트리거).
   - 이렇게 보이면 됩니다: 표 아래에 `판정: (가) 로컬 / (나) 클라우드` 한 줄을 적어 둡니다.

### 나. 한도 확인하기

6. 크롬 새 탭에서 공식 한도 페이지 `https://developers.google.com/apps-script/guides/services/quotas` 를 엽니다. 영어 페이지라면 크롬 주소창 오른쪽의 번역 아이콘으로 한국어로 볼 수 있습니다.
7. 표에서 "Consumer"(일반 구글 계정) 열을 찾아 세 값을 확인합니다. 12강에서 본 메일 수신자(하루 100명)와 트리거 실행 시간(하루 합계 90분)에 더해, 스크립트 하나에 사용자당 트리거는 20개까지입니다.
8. 확인한 값과 오늘 날짜를 판정표 아래에 적습니다. 예: `0928 확인 — 수신자 100/일, 트리거 90분/일, 트리거 20개/스크립트`.

### 다. (나)에 세 줄 붙이기

9. 판정표 문서 맨 위로 올라가, 제목 바로 아래에 <strong>끄는 법</strong>을 먼저 적습니다. 급할 때 찾는 줄이기 때문입니다. 예: `끄는 법: 앱스 스크립트 편집기 왼쪽의 알람 시계 모양 '트리거' → 이 트리거 줄의 점 세 개 → '트리거 삭제'`.
10. 그 아래에 **한도** 한 줄: `한 번 실행에 메일 1통, 수신자는 나 1명`.
11. 그 아래에 **정지선** 두 줄: `같은 주에 이미 보냈으면 보내지 않고 기록만 남긴다`, `실패가 두 번 연속이면 트리거를 스스로 지우고 나에게 알린다`.

### 라. (가)에도 세 줄 붙이기 — 로컬도 한도가 필요합니다

12. (가) 아래에 세 줄을 적습니다.
    - 한도: `한 번에 메모 5개까지`
    - 정지선: `초안이 만들어져도 '검토 필요' 상태로 둔다`
    - 끄는 법: `AGY 대화에서 진행 중인 작업을 멈추고(C1에서 배운 방법), 결과 폴더 01_draft에 5분 동안 새 파일이 더 생기지 않는지 확인한다`
13. 두 자동화 모두에 `생성 성공 ≠ 검증 통과` 칸을 만들고, 사람이 무엇을 확인하면 통과인지 한 줄로 적습니다. 예: `원본에 없는 날짜·이름이 없으면 통과`.
14. 무료 도구가 바뀌거나 멈출 때의 대체 방법을 한 줄 적습니다. 수동 절차도 됩니다. 예: `요약 메일이 안 오면 월요일 점심에 신청 시트를 직접 연다`.

### 마. (선택) (나)를 실제로 켜고 끄는 연습

15. AGY에게 아래 두 번째 요청을 보내 코드를 받습니다. 코드를 편집기에 붙여 넣고 저장하는 방법은 12강 17~28단계와 같습니다(신청 시트에서 '확장 프로그램' → 'Apps Script').
16. 테스트용으로 한 번 손으로 실행해, 내 메일함에 요약이 한 통 오는지 봅니다(권한 승인은 12강 30~35단계).
17. 편집기 왼쪽 '트리거'(알람 시계 모양) → 오른쪽 아래 '트리거 추가'를 누릅니다. '실행할 함수 선택'에 요약 함수, '이벤트 소스 선택'에 '시간 기반', '시간 기반 트리거 유형 선택'에 '주 단위 타이머', 요일은 '매주 월요일', 시간은 '오전 8시~9시'를 고르고, '실패 알림 설정'은 '즉시 알림'으로 둔 뒤 '저장'을 누릅니다.
    - 이렇게 보이면 됩니다: 트리거 목록에 '시간 기반' 한 줄이 생깁니다. 정확히 8시가 아니라 8시에서 9시 사이 어느 때 돕니다.
18. 9단계의 끄는 법을 지금 한 번 해 봅니다. 그 줄에 마우스를 올려 오른쪽 점 세 개 → '트리거 삭제'를 누릅니다. 목록이 비는 것을 확인한 뒤, 17단계로 다시 만듭니다. 한 번도 꺼 보지 않은 자동화는 켜지 않습니다.

(화면의 글자는 버전에 따라 조금 다를 수 있습니다.)

## AI에게 건네는 말

첫 번째 말은 판정만 받는 요청이라 제미나이 웹에서 합니다.

> **어디에 입력하나요:** PC에서 크롬을 열고 주소창에 `https://gemini.google.com` 을 입력해 들어갑니다. 구글 계정으로 로그인돼 있으면 화면 아래쪽에 글을 쓰는 입력칸이 보입니다. 그 칸을 한 번 누르고, 아래 글을 복사(`Ctrl + C`)해 붙여 넣은(`Ctrl + V`) 뒤 `Enter` 를 누르거나 오른쪽의 보내기(제출) 버튼을 누르세요. (여러 줄을 쓸 때는 `Enter` 대신 `Shift + Enter` 로 줄을 바꿉니다 — `Enter` 만 누르면 바로 보내집니다.) 답이 위쪽에 나타나면 끝까지 읽고, 모르는 말이 있으면 "○○가 무슨 뜻이야?" 라고 이어서 물으면 됩니다.
> 화면을 보여 주고 싶으면: 입력칸 왼쪽의 '+' 또는 파일 추가 버튼으로 캡처 이미지(C0 22강의 `Win + Shift + S`)를 올린 뒤 질문을 씁니다.

보낼 글 (첫 번째 요청): `자동화판정표` 문서 안을 누르고 `Ctrl + A` → `Ctrl + C` 로 복사해 `[설계서 붙여넣기]` 자리에 붙여 넣습니다.

> 내 자동화 설계서야: [설계서 붙여넣기]. 이 일을 내 컴퓨터에서 돌릴지, 앱스 스크립트 트리거로 구글 서버에서 돌릴지 다섯 가지 물음(자리에 없어도 돌아야 하나 / 입력 자료 위치 / 밖에 나가면 안 되는 자료인가 / 확인 카드나 권한 승인에 답할 사람 / 누가 어떻게 끄나)으로 판정해 줘. 판정만 하고 코드는 쓰지 마.

답을 읽는 법: AI의 판정이 내 판정과 다르면, 어느 물음에서 갈렸는지 봅니다. 그 물음에 대한 내 답을 한 줄 덧붙여 다시 물어도 됩니다. 결정은 내가 합니다.

두 번째 말은 코드를 받는 요청이라 AGY에게 보냅니다.

> **어디에 입력하나요:** 바탕화면이나 시작 메뉴에서 'Antigravity'를 눌러 AGY를 엽니다. 작업 폴더가 열려 있는지 먼저 봅니다(C1 3강). 화면 아래쪽의 채팅 입력칸(에이전트에게 말을 거는 칸)을 누르고, 아래 글을 붙여 넣은 뒤 `Enter` 로 보냅니다. AGY가 대화 안에 계획이나 확인 카드를 먼저 보여 주면, 바로 승인하지 말고 무엇을 하겠다는지 읽은 뒤 결정합니다(C1 9강).

보낼 글 (두 번째 요청):

> 신청 시트(열: 타임스탬프, 이름, 소속, 신청 과정, 선호 요일, 하고 싶은 말)의 이번 주 신청 현황을 과정별 개수로 요약해 나에게 메일로 보내는 앱스 스크립트를 써 줘. 세 가지를 넣어 줘: ① 한 번 실행에 보내는 메일은 1통, 수신자는 스크립트를 실행하는 내 계정 1명으로 고정 ② 같은 주에 이미 보냈으면 보내지 않고 기록만 남김 ③ 실패가 두 번 연속이면 스스로 트리거를 지우고 나에게 알림. 이름·하고 싶은 말 칸은 요약에 넣지 마. 코드는 작업 폴더에 `주간요약_v01.gs` 파일 하나로 저장하고, 설계서 맨 위에 붙일 "끄는 법" 한 줄도 대화에 써 줘.

답을 읽는 법: 대화에 나온 "끄는 법" 한 줄이 9단계에 내가 적은 것과 같은지 봅니다. 다르면 둘 중 정확한 쪽(실제 편집기에서 해 본 쪽)을 남깁니다.

## 손에 남길 것과 완료 확인

**자동화 판정표(다섯 물음) · 자동화마다 한도 · 정지선 · 끄는 법 세 줄 · 검증 통과 기준 한 줄** (`자동화판정표` 문서)

- [ ] 자동화마다 다섯 물음에 답하고 로컬·클라우드를 판정했다
- [ ] 클라우드 쪽 한도를 공식 문서에서 확인하고 확인한 날짜를 적었다
- [ ] 한도 한 줄을 썼다(횟수·수신자·분량)
- [ ] 정지선 한 줄을 썼다(무엇이 되면 스스로 멈추나)

- [ ] 로컬 자동화에도 한도를 붙였다
- [ ] "생성 성공"과 "검증 통과"를 다른 칸으로 나눴다
