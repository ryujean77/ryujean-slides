# 16강. 자동으로 내보낼 때의 안전장치 — 막고 멈추는 코드

유정근 · 마이웨이 아카데미 | C3 업무 자동화
척추: 12블럭 B11

## 오늘의 목표

자동화가 무언가를 밖으로 내보내는 순간(메일 발송, 공유 폴더 복사, 공개 페이지 갱신) 앞에 **검사 → 정제 → 재검사** 세 겹의 가드를 둡니다. 그리고 하나라도 걸리면 아무것도 내보내지 않는 "닫힌 채로 멈추는(fail-closed)" 규칙을 내 흐름도에 그려 넣습니다.

## 먼저 이해하기

오늘 나오는 말을 먼저 풀어 둡니다.

- **안전장치 / 가드**: 위험한 동작이 일어나기 직전에 조건을 확인하고, 조건에 걸리면 그 동작을 막아 세우는 코드입니다. 이 과정에서는 둘을 같은 뜻으로 씁니다.
- **검사**: 내보낼 내용에 나가면 안 되는 것(전화번호 모양, 이메일 주소 모양 등)이 있는지 코드가 세어 보는 일입니다.
- **정제**: 내보낼 내용에서 필요한 칸만 남기고 나머지를 빼서, 공개용 사본을 새로 만드는 일입니다. 원본은 그대로 둡니다.
- **재검사**: 정제가 끝난 사본에 같은 검사를 한 번 더 하는 일입니다.
- **fail-open(열린 실패)**: 문제가 생겨도 "일단 보내고 경고만" 하는 방식입니다.
- **fail-closed(닫힌 실패)**: "하나라도 걸리면 전부 멈추는" 방식입니다.
- **오탐**: 문제가 없는데 가드가 문제라고 잘못 잡는 일입니다.

무엇을 공개하고 무엇을 지킬지는 C2 19강에서 이미 나눴습니다. 오늘의 질문은 다릅니다. **사람이 매번 보지 않는데도 그 선이 지켜지게 하려면 어떻게 하나?** 사람이 직접 내보낼 때는 눈이 마지막 검사입니다. 자동화가 내보낼 때는 그 눈을 코드로 옮겨 두어야 합니다.

내보내는 일에는 닫힌 실패가 맞습니다. 보내지 못한 메일은 내일 다시 보내면 되지만, 한 번 나간 연락처는 되돌릴 수 없기 때문입니다.

비유하자면 가스 밸브입니다. 요즘 가스레인지는 불꽃이 꺼지면 가스를 저절로 잠급니다. "불이 꺼졌으니 조심하세요"라고 방송만 하는 장치였다면 아무도 믿지 않았을 것입니다. 안전장치는 알려 주는 것이 아니라 잠그는 것입니다.

그리고 한 가지 원칙이 따라옵니다. **검출은 지시를 믿지 않는다.** AI에게 "연락처는 빼고 써 줘"라고 부탁하는 것(지시)과, 결과물에 연락처 모양의 글자가 있는지 코드가 세어 보는 것(검출)은 다른 일입니다. 지시는 대부분 지켜지지만, 가드는 "대부분"을 위해 있는 것이 아닙니다.

## 강사의 시스템에서

강사의 워크스페이스(강사가 AI와 함께 쓰는 작업 폴더 묶음)에는 비공개 코어(남에게 보이면 안 되는 원본 자료를 모아 둔 곳)의 내용을 공개 공간으로 내보내는 동기화 스크립트(두 곳의 내용을 맞춰 복사하는 프로그램)가 둘 있습니다. 하나는 프로젝트 목록을 공개 관제 화면(진행 상황을 한눈에 보여 주는 웹 페이지)으로, 다른 하나는 이 아카데미의 수업 원고를 공개 학습 사이트로 보냅니다. 둘 다 같은 세 겹 구조입니다.

**첫째 겹, 검사.** 등록 후보에 절대 공개 불가 범주(고객 상담 기록, 연구 윤리 심의 자료, 민감·비공개 표시 폴더, 로컬 검색 색인 파일 — 내 컴퓨터 안의 자료를 빨리 찾으려고 만든 목록 파일)를 가리키는 말이 하나라도 있으면, 그 자리에서 실행을 끝냅니다. 경고를 띄우고 계속 가는 것이 아니라 프로그램 자체를 멈춥니다.

**둘째 겹, 정제.** 통과한 후보도 원본 그대로 내보내지 않습니다. 정제 함수(공개용 사본을 만드는 코드 묶음)가 사본을 만들면서 뺄 것을 뺍니다: 내 컴퓨터 속 폴더 경로, "내부" 표시가 붙은 산출물 이름, 아직 대외 배포되지 않은 항목의 산출물 목록(제목과 상태만 남김), 제목·설명 속 통화 녹취 파일명.

**셋째 겹, 재검사.** 정제가 끝난 사본을 한 번 더 훑어, 드라이브 문자(`C:` 처럼 컴퓨터 저장 장치를 가리키는 글자)로 시작하는 경로나 환경 설정 파일(비밀 열쇠 같은 설정값을 담는 파일) 이름이 남아 있으면 다시 멈춥니다. 정제 코드에 구멍이 있어도 재검사가 잡습니다.

이 구조는 실제 사고에서 자랐습니다. 10강에서 본 제목 사고를 추적해 보니, 정제 함수는 경로만 빼고 제목과 설명은 그대로 내보내고 있었습니다. 제목만 고치면 설명 칸에 녹취 파일명이 남는다는 것도 그때 알았고, 그래서 두 칸을 함께 세척하도록 바꿨습니다. 또 한 번은 강사가 앓아누운 동안 에이전트가 대리 결재를 하면서, 새로 등록된 프로젝트 제목에 거래 상대의 실명이 들어간 것을 발견했습니다. 에이전트는 동기화를 **돌리지 않았습니다.** 정제를 거치더라도 제목의 실명은 빠지지 않을 수 있었고, 지금 돌리면 되돌리기 어렵다는 판단이었습니다. 가드가 잡지 못하는 영역에서는 사람이 관문입니다.

학습 사이트용 가드에서는 두 가지를 더 배웁니다.

- **하나만 걸려도 복사 0건.** 원고 전부를 먼저 검사하고, 이메일 주소 · 휴대폰 번호 · 로컬 드라이브 경로 · 저장소 계정 주소 · 토큰(서비스에 들어가는 비밀 열쇠 글자) · 실명 목록 가운데 하나라도 나오면 한 파일도 복사하지 않고 걸린 줄의 위치를 모두 출력합니다. 검사를 통과해도 공개 저장소(누구나 볼 수 있게 파일을 올려 두는 온라인 보관소)에 올리는 마지막 단계는 사람이 확인한 뒤에 합니다. 이 과정의 원고도 공개되기 전에 이 가드를 지나게 되어 있습니다.
- **오탐은 끄지 말고 좁게 연다.** C0 과정은 "내 컴퓨터의 사용자 폴더"를 가르쳐야 해서 원고에 경로 모양의 글자가 나옵니다. 경로 규칙을 그대로 두면 가드는 이것을 로컬 경로로 보고 막습니다. 해결은 가드를 끄는 것이 아니라, <strong>괄호로 된 교육용 자리표시자(예: "(내 계정 이름)") 모양만 허용</strong>하는 것이었습니다. 실제 계정 이름이 들어간 경로는 여전히 막힙니다. 반대로 관제 화면 가드에서는 공개 인용이 가능한 정보(논문의 심의 승인 번호)까지 막던 단어 하나를 목록에서 뺐습니다. 문제는 늘 그 단어가 아니라 "경로"였고, 경로는 다른 규칙이 잡고 있었기 때문입니다. 넓게 막았다가 필요한 만큼만 좁게 여는 순서입니다.

마지막으로, 가드는 스스로를 시험합니다. 두 스크립트 모두 자가 시험 모드(일부러 나쁜 샘플을 넣어 가드가 멈추는지 확인하는 실행 방식)가 있어서, 가짜 상담 기록 제목, 가짜 경로, 가짜 번호를 넣고 **정말로 멈추는지** 확인합니다. 가드를 고친 날에는 이 시험부터 돌립니다. 워크스페이스 헌장(모든 AI와 사람이 지키는 최상위 규칙 문서)에는 "이 가드나 정제를 우회·비활성화·삭제하는 변경은 헌장 위반"이라고 적혀 있습니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다. 실제 사람의 정보는 한 글자도 쓰지 않습니다. PC의 크롬과 AGY로 합니다. 약 60분이 걸립니다.

윤하람 씨는 12강에서 만든 "설문지 → 시트 → 알림" 흐름을 한 단계 넓히려 합니다. 매주 금요일, 수강 신청 시트의 요약을 협업 강사와 함께 쓰는 공유 폴더에 문서로 저장하는 자동화입니다. 그사이 설문지에 `신청 과정`과 `선호 요일` 질문을 더했습니다. 신청 시트에는 이름·소속이 있고, '하고 싶은 말' 칸에 연락처를 적는 사람도 있습니다.

### 가. 흐름도에 가드 그리기 (종이)

1. 3강에서 그린 흐름도(일이 흘러가는 순서를 상자와 화살표로 그린 그림)를 꺼냅니다. "밖으로 나가는 지점"에 빨간 펜으로 동그라미를 칩니다. 하람 씨의 경우 "공유 폴더에 요약 문서 저장"입니다.
2. 그 동그라미 바로 앞에 상자 세 개를 그립니다: `검사` → `정제` → `재검사`. 각 상자 아래에 `걸리면?` 을 적고, 셋 다 `아무것도 저장하지 않고 나에게 알림` 이라고 씁니다.
3. <strong>검사 목록</strong>을 흐름도 옆에 적습니다. 하람 씨의 목록: 휴대폰 번호 모양, 이메일 주소 모양, `이름` 칸의 값, "상담" · "개인" 이라는 단어.
4. <strong>정제 규칙</strong>을 적습니다. 요약에 들어갈 칸만 남기고 나머지 칸은 뺍니다. 하람 씨는 `과정명 · 신청 수 · 선호 요일` 만 남기기로 했습니다. 빼는 목록보다 <strong>남기는 목록</strong>을 정하는 편이 안전합니다. 설문지에 새 질문이 생겨도 저절로 빠지기 때문입니다.
5. <strong>재검사</strong>는 3번 목록을 정제된 결과에 한 번 더 적용하는 것입니다. 새 목록을 따로 만들지 않습니다. 흐름도의 `재검사` 상자 옆에 `3번 목록 다시` 라고 적습니다.

### 나. 시험용 시트와 폴더 준비하기

6. 크롬에서 `https://drive.google.com` 을 열고, '+ 새로 만들기' → '새 폴더'로 `시험_요약저장` 폴더를 만듭니다. 실제 공유 폴더 대신 쓰는, 나만 보는 시험용 폴더입니다.
7. 그 폴더를 두 번 눌러 들어간 뒤, 크롬 주소창의 주소를 봅니다. 주소 맨 끝 `folders/` 뒤에 붙은 긴 글자가 이 폴더의 ID(폴더마다 붙은 고유 이름표)입니다. 이 부분만 마우스로 끌어 선택하고 `Ctrl + C` 로 복사해 메모장에 붙여 둡니다.
8. 같은 폴더에서 '+ 새로 만들기' → 'Google 스프레드시트'로 `시험_신청요약` 시트를 만듭니다.
9. 첫 행에 칸 이름을 적습니다: `타임스탬프 / 이름 / 소속 / 신청 과정 / 선호 요일 / 하고 싶은 말`.
10. <strong>자가 시험 샘플</strong> 세 줄을 적습니다. 모두 가짜입니다.
    - 2행(깨끗한 줄): 이름 `시험A`, 소속 `연습`, 신청 과정 `기록 강좌`, 선호 요일 `화`, 하고 싶은 말 `기대됩니다`
    - 3행(번호가 든 줄): 하고 싶은 말 칸에 010으로 시작하고 나머지를 모두 0으로 채운 가짜 휴대폰 번호를 적습니다.
    - 4행(이메일이 든 줄): 하고 싶은 말 칸에 `@` 와 `example.com` 을 이어 붙인 가짜 주소를 적습니다. `example.com` 은 시험용으로 비워 둔 주소라 실제 사람에게 닿지 않습니다.
    - 타임스탬프 칸은 아무 날짜나 적습니다.

### 다. AGY에게 코드 받기

11. AGY에게 아래 첫 번째 요청문을 보냅니다. 계획에 "작업 폴더에 `.gs` 파일 하나를 만든다"만 있는지 보고 승인합니다.
12. 코드를 받으면 곧바로 두 번째 요청문을 보내, "걸렸는데도 저장이 실행될 수 있는 길"이 있는지 점검받습니다. 있다는 답이 나오면 고쳐 달라고 하고, 다시 두 번째 요청문을 보냅니다. "없다"는 답이 나올 때까지 편집기에 붙여 넣지 않습니다.

### 라. 편집기에 붙여 넣고 폴더 ID 넣기

13. `시험_신청요약` 시트 탭에서 위쪽 메뉴 '확장 프로그램' → 'Apps Script'를 누릅니다. 프로젝트 이름을 `요약가드_v01` 로 바꿉니다(12강 19단계와 같은 방법).
14. AGY 작업 폴더의 `.gs` 파일을 파일 탐색기에서 찾아 메모장으로 열고, 모두 복사해 편집기 코드 칸에 붙여 넣은 뒤 `Ctrl + S` 로 저장합니다(12강 24~28단계와 같은 방법).
15. 편집기 맨 왼쪽 톱니바퀴 모양 '프로젝트 설정'을 누릅니다. 화면 아래쪽 '스크립트 속성'에서 '스크립트 속성 추가'를 누릅니다. '속성' 칸에 `SUMMARY_FOLDER_ID`, '값' 칸에 7단계에서 복사해 둔 폴더 ID를 붙여 넣고 '스크립트 속성 저장'을 누릅니다.
    - 이렇게 보이면 됩니다: 스크립트 속성 표에 `SUMMARY_FOLDER_ID` 한 줄이 보입니다. 코드에는 폴더 ID가 글자로 들어가지 않습니다.

### 마. 가드가 정말 멈추는지 시험하기

16. 편집기 맨 왼쪽 '편집기'(< > 모양)로 돌아옵니다. 도구 줄의 함수 이름 칸에서 **시험 함수**(AGY가 알려 준 이름, 예: `selfTestGuard`)를 고르고 '▷ 실행'을 누릅니다. 권한 승인 창이 뜨면 12강 30~35단계처럼 권한 목록을 읽고 승인합니다. 이번 권한 목록에는 시트 보기, 드라이브 파일 만들기, 내게 메일 보내기가 있을 수 있습니다. 그 밖의 것이 있으면 멈추고 AGY에게 이유를 묻습니다.
17. 아래 '실행 로그' 칸을 읽습니다. 시험 함수는 세 경우의 결과를 적어야 합니다.
    - 이렇게 보이면 됩니다: "깨끗한 샘플 → 통과", "번호 샘플 → 멈춤(3행)", "이메일 샘플 → 멈춤(4행)" 같은 줄이 보입니다.
18. 이번에는 **본 함수**(예: `saveWeeklySummary`)를 골라 실행합니다. 시트에 나쁜 줄(3·4행)이 있으므로 문서가 생기면 안 됩니다.
    - 이렇게 보이면 됩니다: `시험_요약저장` 폴더에 새 문서가 **없고**, Gmail 받은편지함에 "몇 번째 행에서 무엇이 걸렸는지" 알리는 메일이 한 통 와 있습니다.
19. 시트에서 3행과 4행을 지웁니다. 행 번호 '3'을 누르고 `Shift` 를 누른 채 '4'를 눌러 두 줄을 선택한 뒤, 마우스 오른쪽 단추 → '행 3-4 삭제'를 고릅니다. 본 함수를 다시 실행합니다.
    - 이렇게 보이면 됩니다: `시험_요약저장` 폴더에 요약 문서가 하나 생기고, 열어 보면 `과정명 · 신청 수 · 선호 요일` 만 있고 이름·소속·하고 싶은 말은 없습니다.
20. 17~19단계 가운데 하나라도 기대와 다르면 승인하지 않습니다. 실행 로그의 문구를 복사해 AGY에게 보여 주고 고칩니다.

### 바. 오탐 처리와 기록

21. 오탐이 나오면(예: 과정명 `2026 기록 강좌` 의 숫자가 번호로 잡힘) 가드를 끄지 말고, AGY에게 "이 모양만 허용하는 예외를 한 줄 추가해 줘"라고 합니다. 그리고 16~19단계의 시험을 다시 돌립니다.
22. 흐름도의 빨간 동그라미 옆에 `가드 고친 날에는 시험 먼저` 라고 적습니다.
23. 가드가 멈출 때마다 날짜와 걸린 이유를 흐름도 뒷면에 한 줄씩 적습니다. 20강에서 이 줄 수를 셉니다.

## AI에게 건네는 말

두 요청 모두 AGY에게 보냅니다.

> **어디에 입력하나요:** 바탕화면이나 시작 메뉴에서 'Antigravity'를 눌러 AGY를 엽니다. 작업 폴더가 열려 있는지 먼저 봅니다(C1 3강). 화면 아래쪽의 채팅 입력칸(에이전트에게 말을 거는 칸)을 누르고, 아래 글을 붙여 넣은 뒤 `Enter` 로 보냅니다. AGY가 대화 안에 계획이나 확인 카드를 먼저 보여 주면, 바로 승인하지 말고 무엇을 하겠다는지 읽은 뒤 결정합니다(C1 9강).

보낼 글 (첫 번째 요청 — 코드 받기):

> 수강 신청 시트의 요약을 매주 드라이브 폴더에 구글 문서로 저장하는 앱스 스크립트를 써 줘. 시트 칸은 타임스탬프, 이름, 소속, 신청 과정, 선호 요일, 하고 싶은 말이야. 순서는 검사 → 정제 → 재검사 → 저장이야. 검사에서 휴대폰 번호 모양, 이메일 주소 모양, '이름' 칸의 값, '상담'·'개인' 단어 가운데 하나라도 나오면 문서를 만들지 말고, 무엇이 몇 번째 행에서 걸렸는지 나에게만 메일로 알려 줘(받는 사람은 스크립트를 실행하는 내 계정 주소를 코드가 스스로 읽게). 정제는 '과정명·신청 수·선호 요일' 세 가지만 남기는 방식으로 해 줘(빼는 목록이 아니라 남기는 목록). 재검사는 정제된 결과에 같은 검사를 한 번 더 하는 거야. 저장할 폴더 ID는 코드에 쓰지 말고 스크립트 속성 `SUMMARY_FOLDER_ID` 에서 읽어. 가짜 샘플 세 행(깨끗한 행, 가짜 번호 행, 가짜 이메일 행)으로 가드가 실제로 멈추는지 실행 로그에 적는 시험 함수도 따로 만들어 줘. 발송이나 공유 권한 변경은 코드에 넣지 마. 코드는 작업 폴더에 `요약가드_v01.gs` 파일 하나로 저장하고, 본 함수와 시험 함수의 이름을 대화에 알려 줘.

답을 읽는 법: 함수 이름 두 개를 종이에 옮겨 둡니다. 16단계와 18단계에서 이 이름을 고릅니다.

보낼 글 (두 번째 요청 — 구멍 찾기):

> 방금 만든 `요약가드_v01.gs` 를 읽고, 검사에 걸렸는데도 파일이 만들어지거나 메일이 알림 말고 다른 곳으로 나갈 수 있는 경로가 있는지만 찾아 줘. 오류가 나서 검사가 중간에 멈췄을 때 저장이 실행되는지도 확인해 줘. 코드는 고치지 말고 찾은 결과만 알려 줘.

## 손에 남길 것과 완료 확인

**"밖으로 나가는 지점" 표시와 세 겹 가드가 그려진 흐름도 · 검사 목록 · 남기는 목록 · 가드 자가 시험 결과**

- [ ] 흐름도에서 밖으로 나가는 지점을 모두 찾아 표시했다
- [ ] 그 앞에 검사 → 정제 → 재검사를 두었다
- [ ] 세 겹 모두 "걸리면 아무것도 내보내지 않는다"로 정했다
- [ ] 정제를 "빼는 목록"이 아니라 "남기는 목록"으로 정했다
- [ ] 검사 목록을 AI에게 부탁하는 문장이 아니라 코드가 세는 규칙으로 두었다
- [ ] 가짜 샘플로 가드가 실제로 멈추는 것을 확인했다(나쁜 줄이 있을 때 폴더에 문서가 없었다)
- [ ] 검사 도중 오류가 나도 저장이 실행되지 않는 것을 확인했다
- [ ] 오탐은 가드를 끄지 않고 좁은 예외로 해결했다
- [ ] 가드가 잡지 못하는 판단(실명이 든 제목 등)은 사람 관문으로 남겼다

가드가 너무 자주 멈춘다면 실패가 아니라 초기값이 잘 작동하는 것입니다. 한 번 멈출 때마다 "무엇이 걸렸나"를 기록해 두면, 20강에서 그 숫자가 가드를 다듬는 근거가 됩니다.
