# 3강. 흐름도 한 장 — 입력·처리·결재·출력·기록

유정근 · 마이웨이 아카데미 | C3 업무 자동화
척추: 12블럭 B10

## 오늘의 목표

1강의 자동화를 **입력 → 처리 → 결재 → 출력 → 기록** 다섯 칸짜리 흐름도 한 장으로 그리고, "승인하면 정확히 무엇이 일어나는가"에 답할 수 있게 합니다.

## 먼저 이해하기

자동화가 무서운 이유는 대개 속이 보이지 않기 때문입니다. 흐름도는 그 속을 한 장에 펼쳐 놓는 일입니다. 다섯 칸이면 충분합니다.

- **입력**: 무엇이, 어디로 들어오는가 (예: 음성 메모가 드라이브 인박스 폴더로)
- **처리**: 누가 무엇을 만드는가 (예: AI가 진행 메모 초안을)
- **결재**: 어디서 사람이 멈추는가 (2강의 멈춤 지점)
- **출력**: 승인하면 무엇이 생기는가 (파일, 일정, 할 일, 알림)
- **기록**: 무엇이 언제 누구 판단으로 지나갔는지 어디에 남는가

앞의 네 칸은 누구나 그립니다. 다섯 번째 칸이 빠지기 쉽습니다. 기록이 없으면 자동화가 한 달 뒤에 무엇을 했는지 아무도 설명하지 못합니다. 실패를 고칠 수도, 잘 된 것을 잴 수도 없습니다.

비유하자면 택배 송장입니다. 물건이 접수되고, 분류되고, 배송 기사가 서명을 받고, 문 앞에 놓입니다. 그리고 그 모든 순간이 조회 화면에 한 줄씩 남습니다. 물건이 사라졌을 때 우리가 찾아가는 곳은 창고가 아니라 그 기록입니다.

## 강사의 시스템에서

강사의 통화 자동화는 드라이브 안의 번호 붙은 폴더 다섯 개로 흐름이 보입니다. 01 인박스(녹취 원문) → 02 기획 초안 → 03 결재 완료 → 04 최종 산출물 → 05 웹 문서. 파일이 어느 폴더에 있는지만 보면 그 일이 어디까지 왔는지 압니다. 실사 때 숫자는 인박스 62건, 초안 40건, 결재 완료 17건이었습니다. 흐름도가 있었기에 **병목이 03번 관문 하나라는** 진단이 한눈에 나왔습니다.

흐름도는 안전 점검에도 쓰였습니다. 대리 결재를 하기 전에 가장 먼저 확인한 질문은 "승인하면 통화 내용이 공개되는가"였습니다. 승인 경로를 끝까지 따라가 출력 칸을 모두 적었습니다. 최종 문서 생성, 초안을 결재 완료 폴더로 이동, 웹 문서 생성, 내부 목록에 등록, 캘린더·할 일 등록, 결재 스레드 회신. 여섯 가지 모두 비공개 영역 안이었습니다. 이름에 "Published"가 붙은 폴더도 실제로는 외부 배포가 아니었습니다. 공개 배포는 사람이 별도로 실행할 때만, 그것도 차단 장치를 통과해야만 일어났습니다. **출력 칸을 빠짐없이 적어 보는 것이** 곧 안전 점검이었습니다.

기록 칸에는 결재 상태를 적는 원장과, 덧붙이기만 하는 감사 기록이 있습니다. 한 번 적힌 줄은 고치지 않고 아래에 새 줄을 더합니다. 그래서 무엇이 언제 누구 판단으로 지나갔는지 되짚을 수 있습니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다.

1. 종이 한 장을 가로로 놓고 다섯 칸을 그립니다: 입력 / 처리 / 결재 / 출력 / 기록.
2. 윤하람 씨는 입력 칸에 씁니다. "수업 직후 휴대폰 받아쓰기로 남긴 메모 → 드라이브 `00_inbox` 폴더." C2 8강에서 표준 폴더에 둔 인박스를, 휴대폰에서도 넣을 수 있게 드라이브에 둔 것입니다.
3. 처리 칸: "AI가 메모를 읽고 진행 메모 초안을 만들어 `01_draft` 폴더에 넣는다. 원본 메모는 그대로 둔다."
4. 결재 칸: 2강의 멈춤 지점표를 옮깁니다. "초안을 읽고 승인·수정·보류 중 하나를 고른다. 판단 기준: 날짜와 준비물이 원문과 맞는가."
5. 출력 칸에는 승인했을 때 생기는 것을 **하나도 빼지 않고** 씁니다. "진행 메모를 `02_approved`로 옮김, 다음 수업 준비물을 할 일에 등록." 윤하람 씨는 적다가 "수강생 요약 발송"을 출력 칸에서 지웠습니다. 그것은 2강에서 "본인만"으로 정한 일이기 때문입니다.
6. 기록 칸: "시트 한 장에 한 줄씩 — 날짜, 원본 파일 이름, 초안 파일 이름, 판단(승인·수정·보류), 한 줄 사유."
7. 화살표를 그리고, 결재 칸에서 "수정"이면 처리 칸으로, "보류"면 멈춘 채로 남는 되돌이 화살표를 더합니다.
8. 완성한 흐름도를 보며 스스로 묻습니다. "승인 버튼을 누르면 정확히 무엇이 일어나는가?" 출력 칸을 읽는 것만으로 답이 나오면 됩니다.

## AI에게 건네는 말

> 아래는 내 자동화를 설명한 글이다. 이것을 '입력 / 처리 / 결재 / 출력 / 기록' 다섯 칸 표로 정리해 줘. 내가 적지 않은 단계를 네가 채워 넣지 말고, 빠진 것 같은 칸에는 '확인 필요'라고만 써 줘. 특히 출력 칸에 밖으로 나가는 행동(발송·공유·공개)이 있으면 굵게 표시해 줘.

> 이 흐름도를 머메이드(mermaid) 흐름도 코드로 바꿔 줘. 결재 칸은 다른 모양으로 그리고, '수정'과 '보류'의 되돌이 화살표를 넣어 줘.

## 손에 남길 것과 완료 확인

**흐름도 한 장**

다섯 칸이 모두 채워져 있고, 결재 칸에 판단 기준이 한 줄 있으며, 출력 칸만 읽고도 "승인하면 무엇이 일어나는가"에 답할 수 있으면 완료입니다. 기록 칸이 "나중에"로 비어 있으면 완료가 아닙니다. 시트 한 장, 문서 한 장이라도 위치를 정해 적습니다. 이 흐름도는 4강 설계서의 한가운데에 들어갑니다.
