# 17강. OSMU — 하나의 원천, 여러 상품

유정근 · 마이웨이 아카데미 | C2 자료관리론

정본 교시: 4-1 지식 상품화 및 OSMU(One Source Multi Use) 퍼블리싱 전략

## 오늘의 목표

검수된 원형 사례 한 편을 정하고, 그 원형에서 대상이 다른 파생물 두 개를 설계해 "그대로 가져갈 것 / 새로 조정할 것"을 표로 나눕니다.

## 먼저 이해하기

<strong>OSMU</strong>(One Source Multi Use, 원소스 멀티유즈 — 하나의 원천을 여러 쓰임으로 펼치는 방식)는 한 이야기로 책도 내고 드라마도 만드는 것처럼, 한 번 잘 만든 내용을 여러 모양으로 내보내는 일입니다. 정본은 이것을 자료관리 체계가 책·강의·기관 워크숍·컨설팅으로 이어지는 길로 설명합니다. 15강이 한 원천에서 문서 여러 개를 뽑는 **작업 방식**이었다면, 오늘은 그 원천을 **서로 다른 사람에게 가닿는 상품**으로 펼치는 설계입니다.

오늘 쓰는 낱말 둘을 맞춰 둡니다.

- <strong>원형 사례</strong>: 한 번 실제로 겪은 일을 정해진 칸에 맞춰 적어 둔 기준 이야기. 모든 파생물은 여기서 사실을 가져옵니다.
- <strong>파생물</strong>: 원형에서 대상과 길이를 바꿔 뽑아낸 결과물. 블로그 글, 제안서, 강의 한 차시 같은 것입니다.

원형은 한 편의 사례로 일곱 칸을 채워 만듭니다. **문제 상황 → 원자료 → 적용 조건 → 판단과 변경 → 결과 → 반례(이 판단이 맞지 않는 경우) → 출처**. 원형에는 사례 번호·버전·기준일·승인 상태를 붙입니다. 블로그와 강의와 책이 서로 다른 사실을 말하기 시작하면 원천은 무너집니다. 그래서 사실이 바뀌면 파생물을 고치지 않고 원형을 고친 뒤 파생물을 다시 뽑습니다.

비유하자면 한 그루 나무에서 목재를 켜는 일입니다. 같은 나무에서 기둥도, 책상 상판도, 젓가락도 나옵니다. 쓰임에 따라 자르는 굵기와 다듬는 결은 다르지만, 나이테는 바꿀 수 없습니다. 원형의 사실과 판단 근거가 그 나이테입니다.

## 실제 기록에서 배운 한 줄

강사의 대면 강의계획서(4주판)는 실제로 한 기관의 시니어 과정 20차시 커리큘럼으로 파생되었습니다(기관명은 \*\*텍대학으로 가립니다). 두 문서를 나란히 펴 보면 무엇을 지키고 무엇을 바꿨는지가 선명합니다.

| 그대로 가져간 것 (나이테) | 새로 조정한 것 (결) |
|---|---|
| 원본·작업본·공유본·백업의 구별 | 자료 목록 30개 → 10개 |
| 자료 지도와 저장소 3~5곳 점검 | 검색 제한 시간 문항당 2분 → 3분 |
| 같은 난이도의 사전·사후 측정, "5문제 중 4개" 기준 | 8시간 → 20차시, 바이브 코딩·업무 자동화 부 추가 |
| 잘못된 최신본을 찾으면 실패로 기록 | 한 차시 한 가지 조작, 짝 학습, 큰 글씨 실습지 |
| 판단 기록 세 줄(바꿈 / 이유 / 다음 예외), 주 15분 점검 | 결과물을 경력·기술 포트폴리오로 연결 |

대상이 바뀌자 속도와 분량은 크게 달라졌지만, 평가 기준과 검증 방식은 거의 그대로 남았습니다. 파생에서 바꿔야 할 것은 전달의 결이고, 지켜야 할 것은 판단의 뼈대입니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다.

준비물: PC, 크롬, 메모장, 15강의 `20_notes\원천_60분수업_v01.md`.

**가. 원형 사례 쓰기 (메모장)**

1. 윤하람 씨는 원형 사례 하나를 고릅니다. "90분 개인 기기 수업을 60분 공용 기기 수업으로 바꾼 일"(가상 자료 S01~S03). 나도 최근에 "조건이 바뀌어 방식을 바꾼 일" 하나를 고릅니다.
2. '시작' → `메모장` 을 열고 아래 틀을 붙여 넣은 뒤, 일곱 칸을 한두 줄씩 채웁니다.

   ```markdown
   # CASE-001 / v0.1 / 기준일 2026-09-01 / 검토 중
   ## 1. 문제 상황
   ## 2. 원자료
   ## 3. 적용 조건
   ## 4. 판단과 변경
   ## 5. 결과
   ## 6. 반례
   ## 7. 출처
   ```

   하람 씨의 예: 문제 상황 "공용 기기 60분 수업 의뢰", 원자료 "S01·S02·S03", 판단과 변경 "개인 계정 연결 실습을 뺐다".

3. 반례 칸에는 "이 판단이 맞지 않는 경우"를 적습니다. 하람 씨는 "개인 기기 과정이라고 계정 연결을 자동으로 되살리지는 않는다 — 시간과 학습 목표를 다시 본다"를 적었습니다.
4. '파일' → '다른 이름으로 저장' → 작업 폴더의 `20_notes` → '파일 형식' '모든 파일 (*.*)' → 파일 이름 `CASE-001_60분전환_v01.md` 로 저장합니다.
   → 이렇게 보이면 됩니다: 메모장 제목이 `CASE-001_60분전환_v01.md` 로 바뀝니다.

**나. 파생물 두 개 설계하기 (제미나이 → 메모장)**

5. 대상이 다른 파생물 두 개를 고릅니다. 예) 인터넷 검색으로 들어오는 방문자용 블로그 한 편, 가상 기관 '새봄평생학습관' 담당자용 2쪽 제안서.
6. 원형 파일 전체를 `Ctrl + A` → `Ctrl + C` 로 복사합니다.
7. 아래 "AI에게 건네는 말"의 "어디에 입력하나요"대로 제미나이를 열고 '새 채팅'을 누른 뒤, 요청문을 붙여 넣고 `Shift + Enter` 로 줄을 바꿔 원형 사례를 이어 붙여 보냅니다.
   → 이렇게 보이면 됩니다: 파생물 두 개에 대한 표가 나오고, 칸은 '대상과 길이 / 그대로 가져올 것 / 새로 조정할 것 / 쓰면 안 되는 것'입니다.
8. 표를 그대로 받지 않고 내 판단으로 고칩니다. 하람 씨의 기준: 블로그는 "사건과 방법"을 가져오고 "검색 의도와 도입"을 새로 씁니다. 제안서는 "업무 효과와 완료 기준"을 가져오고 "조직의 권한과 인수인계"를 새로 씁니다.
9. 두 파생물 어디에도 원형에 없는 성과 수치나 시간 절감 주장이 없는지 확인합니다. 이 사례는 문장과 절차를 재사용한 것이지, 성과가 측정된 사례가 아닙니다.
10. 고친 표를 메모장에 붙여 `20_notes` 에 `파생설계_CASE-001_v01.md` 로 저장합니다(4번과 같은 방법).

✖ 제미나이가 표 대신 블로그 글을 통째로 써 주면: 그 글은 쓰지 않습니다. 이어서 "글은 쓰지 말고 설계표만 만들어 줘" 라고 보냅니다.

(제미나이 화면의 글자는 버전에 따라 조금 다를 수 있습니다.)

## AI에게 건네는 말

> **어디에 입력하나요:** PC에서 크롬을 열고 주소창에 `https://gemini.google.com` 을 입력해 들어갑니다. 구글 계정으로 로그인돼 있으면 화면 아래쪽에 글을 쓰는 입력칸이 보입니다. 그 칸을 한 번 누르고, 아래 글을 복사(`Ctrl + C`)해 붙여 넣은(`Ctrl + V`) 뒤 `Enter` 를 누르거나 오른쪽의 보내기(제출) 버튼을 누르세요. (여러 줄을 쓸 때는 `Enter` 대신 `Shift + Enter` 로 줄을 바꿉니다 — `Enter` 만 누르면 바로 보내집니다.) 답이 위쪽에 나타나면 끝까지 읽고, 모르는 말이 있으면 "○○가 무슨 뜻이야?" 라고 이어서 물으면 됩니다.
> 화면을 보여 주고 싶으면: 입력칸 왼쪽의 '+' 또는 파일 추가 버튼으로 캡처 이미지(C0 22강의 `Win + Shift + S`)를 올린 뒤 질문을 씁니다.

요청문 아래에 원형 사례 전체를 이어 붙여 보냅니다(7번).

> 아래 원형 사례를 읽고, '블로그 한 편'과 '기관 담당자용 2쪽 제안서' 두 파생물의 설계표를 만들어 줘. 칸은 '대상과 길이 / 원형에서 그대로 가져올 것 / 새로 조정할 것 / 원형에 없어서 쓰면 안 되는 것'이다. 원형에 없는 성과나 수치는 '쓰면 안 되는 것' 칸에만 적어 줘. 블로그 글이나 제안서 본문은 쓰지 마.

## 손에 남길 것과 완료 확인

**원형 사례 1편(`CASE-001_…_v01.md`) · 파생물 설계표 2개(`파생설계_…_v01.md`)**

원형 사례에 일곱 칸이 모두 있고, 사례 번호·버전·기준일·상태가 맨 위에 붙어 있는지 확인합니다. 파생물 설계표 두 개는 "그대로 가져갈 것"이 서로 겹쳐야 정상입니다. 겹치는 부분이 전혀 없다면 원형이 하나가 아니라는 신호이니 원형부터 다시 봅니다. 반례 칸을 채우지 못했다면 비워 두지 말고 "아직 반례 없음, 다음 적용 때 확인"이라고 적습니다.
