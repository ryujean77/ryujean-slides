# 17강. OSMU — 하나의 원천, 여러 상품

유정근 · 마이웨이 아카데미 | C2 자료관리론

정본 교시: 4-1 지식 상품화 및 OSMU(One Source Multi Use) 퍼블리싱 전략

## 오늘의 목표

검수된 원형 사례 한 편을 정하고, 그 원형에서 대상이 다른 파생물 두 개를 설계해 "그대로 가져갈 것 / 새로 조정할 것"을 표로 나눕니다.

## 먼저 이해하기

OSMU(One Source Multi Use, 원소스 멀티유즈)는 하나의 원천을 여러 쓰임으로 펼치는 방식입니다. 정본은 이것을 자료관리 체계가 책·강의·기관 워크숍·컨설팅으로 이어지는 길로 설명합니다. 15강이 한 원천에서 문서 여러 개를 뽑는 **작업 방식**이었다면, 오늘은 그 원천을 **서로 다른 사람에게 가닿는 상품**으로 펼치는 설계입니다.

원형은 한 편의 사례로 만듭니다. **문제 상황 → 원자료 → 적용 조건 → 판단과 변경 → 결과 → 반례 → 출처**. 원형에는 사례 번호·버전·기준일·승인 상태를 붙입니다. 블로그와 강의와 책이 서로 다른 사실을 말하기 시작하면 원천은 무너집니다. 그래서 사실이 바뀌면 파생물을 고치지 않고 원형을 고친 뒤 파생물을 다시 뽑습니다.

비유하자면 한 그루 나무에서 목재를 켜는 일입니다. 같은 나무에서 기둥도, 책상 상판도, 젓가락도 나옵니다. 쓰임에 따라 자르는 굵기와 다듬는 결은 다르지만, 나이테는 바꿀 수 없습니다. 원형의 사실과 판단 근거가 그 나이테입니다.

## 실제 기록에서 배운 한 줄

강사의 대면 강의계획서(4주판)는 실제로 한 기관의 시니어 과정 20차시 커리큘럼으로 파생되었습니다(기관명은 **텍대학으로 가립니다). 두 문서를 나란히 펴 보면 무엇을 지키고 무엇을 바꿨는지가 선명합니다.

| 그대로 가져간 것 (나이테) | 새로 조정한 것 (결) |
|---|---|
| 원본·작업본·공유본·백업의 구별 | 자료 목록 30개 → 10개 |
| 자료 지도와 저장소 3~5곳 점검 | 검색 제한 시간 문항당 2분 → 3분 |
| 같은 난이도의 사전·사후 측정, "5문제 중 4개" 기준 | 8시간 → 20차시, 바이브 코딩·업무 자동화 부 추가 |
| 잘못된 최신본을 찾으면 실패로 기록 | 한 차시 한 가지 조작, 짝 학습, 큰 글씨 실습지 |
| 판단 기록 세 줄(바꿈 / 이유 / 다음 예외), 주 15분 점검 | 결과물을 경력·기술 포트폴리오로 연결 |

대상이 바뀌자 속도와 분량은 크게 달라졌지만, 평가 기준과 검증 방식은 거의 그대로 남았습니다. 파생에서 바꿔야 할 것은 전달의 결이고, 지켜야 할 것은 판단의 뼈대입니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다.

1. 윤하람 씨는 원형 사례 하나를 고릅니다. "90분 개인 기기 수업을 60분 공용 기기 수업으로 바꾼 일"(워크북 가상 자료 S01~S03).
2. 원형을 일곱 칸으로 채웁니다. 반례 칸에는 "개인 기기 과정이라고 계정 연결을 자동으로 되살리지는 않는다 — 시간과 학습 목표를 다시 본다"를 적습니다.
3. 원형 맨 위에 "CASE-001 / v0.1 / 기준일 2026-09-01 / 검토 중"을 붙입니다.
4. 대상이 다른 파생물 두 개를 고릅니다. 예) 검색 방문자용 블로그 한 편, 가상 기관 '새봄평생학습관' 담당자용 2쪽 제안서.
5. 파생물마다 표를 만듭니다. 블로그는 "사건과 방법"을 가져오고 "검색 의도와 도입"을 새로 씁니다. 제안서는 "업무 효과와 완료 기준"을 가져오고 "조직의 권한과 인수인계"를 새로 씁니다.
6. 두 파생물 어디에도 원형에 없는 성과 수치나 시간 절감 주장이 없는지 확인합니다. 이 사례는 문장과 절차를 재사용한 것이지, 성과가 측정된 사례가 아닙니다.

## AI에게 건네는 말

> 첨부한 원형 사례를 읽고, '블로그 한 편'과 '기관 담당자용 2쪽 제안서' 두 파생물의 설계표를 만들어 줘. 칸은 '대상과 길이 / 원형에서 그대로 가져올 것 / 새로 조정할 것 / 원형에 없어서 쓰면 안 되는 것'이다. 원형에 없는 성과나 수치는 '쓰면 안 되는 것' 칸에만 적어 줘.

## 손에 남길 것과 완료 확인

**원형 사례 1편 · 파생물 설계표 2개**

원형 사례에 일곱 칸이 모두 있고, 사례 번호·버전·기준일·상태가 붙어 있는지 확인합니다. 파생물 설계표 두 개는 "그대로 가져갈 것"이 서로 겹쳐야 정상입니다. 겹치는 부분이 전혀 없다면 원형이 하나가 아니라는 신호이니 원형부터 다시 봅니다. 반례 칸을 채우지 못했다면 비워 두지 말고 "아직 반례 없음, 다음 적용 때 확인"이라고 적습니다.
