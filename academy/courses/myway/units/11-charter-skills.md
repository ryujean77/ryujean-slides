# 11강. 헌장과 스킬 — 에이전트가 가장 먼저 읽는 문서

유정근 · 마이웨이 아카데미 | C2 자료관리론

정본 교시: 3-1 AI 에이전트 아키텍처와 바이브 코딩의 이해 · 4-2 지속 가능한 워크스페이스 커스터마이징 (강사의 실제 워크스페이스 해부)

## 오늘의 목표

내 작업 공간의 헌장 한 장과 스킬 한 개의 초안을 쓰고, 에이전트가 그것을 실제로 읽었는지 증거로 확인합니다.

## 먼저 이해하기

새 직원이 첫 출근을 하면 두 가지를 받습니다. 모든 일에 통하는 **사내 규정 한 장**과, 특정 업무를 할 때 꺼내 보는 **업무 매뉴얼 묶음**입니다. 에이전트에게 헌장은 사내 규정이고, 스킬은 업무 매뉴얼입니다.

**헌장**은 모든 작업의 첫머리에 읽히는 문서입니다. 무엇을 먼저 읽을지, 무엇을 절대 하지 않을지, 결과물을 어디에 둘지, 어떤 말투로 쓸지, 무엇은 사람이 정할지를 적습니다. 매번 읽히므로 **짧고 단단해야** 합니다.

**스킬**은 반복되는 한 가지 일의 절차를 담은 폴더입니다. "강의 안내문 쓰기", "UI 검수하기"처럼 일 하나에 스킬 하나입니다. 그 일을 할 때만 열리므로 **자세해도 됩니다.** 6강에서 배운 암묵지 캡슐화가 가장 실용적인 모양으로 굳은 것이 스킬입니다. 내가 늘 머릿속으로 밟던 순서를 문서로 꺼내 두면, 에이전트는 매번 같은 순서를 밟습니다.

## 강사의 실제 워크스페이스 해부

구조만 봅니다. 헌장의 원문은 싣지 않습니다.

- **입구 파일 셋.** 에이전트 도구마다 작업을 시작할 때 자동으로 찾는 파일 이름이 다릅니다(예: Claude Code는 `CLAUDE.md`). 강사는 도구별 입구 파일에 "헌장을 가장 먼저 읽으라"는 안내만 두고, 규칙 본문은 헌장 한 곳에만 둡니다. 규칙이 여러 곳에 흩어지면 어느 쪽이 맞는지 다투게 되기 때문입니다. 2강의 단일 진실 공급원이 규칙에도 적용된 셈입니다.
- **헌장 하나.** 용어 정의, 핵심 원칙, 작업 환경, 코딩·검증 기준, 표준 작업 순서, 에이전트 행동 수칙, 도구별 맞춤 규칙, 답변 양식의 여덟 장으로 되어 있습니다. 여러 조항은 처음부터 있던 것이 아니라, 실제로 문제가 생긴 뒤 "다음부터는 이렇게 한다"를 적어 넣은 것입니다.
- **스킬 폴더.** 스킬 하나가 폴더 하나입니다. 폴더 안의 `SKILL.md` 첫머리에 **이름**과 <strong>설명(언제 이 스킬을 쓰는지, 어떤 말이 나오면 켜는지)</strong>을 적고, 본문에 절차와 점검표를 씁니다. 필요하면 보조 스크립트를 함께 둡니다.
- **공개 예시 한 개.** 웹 화면 검수 스킬은 "색이 예쁜가" 같은 감상 대신 접근성·포커스·폼·애니메이션·글꼴·내용 넘침·이미지·성능의 여덟 영역 점검표로 검수하게 합니다. 사람마다 달랐던 눈대중을 같은 기준표로 바꾼 것이 이 스킬의 가치입니다.

## 실제 기록에서 배운 한 줄

워크스페이스 초기에는 에이전트가 헌장을 열어 보지 않고 기억과 짐작으로 답해 규칙이 빠지는 일이 있었습니다. 그래서 "가장 먼저 헌장을 연다"를 첫 원칙으로 올리고, **답변 첫 줄에 이번에 열어 본 파일 목록을 적게** 했습니다. 읽으라고 쓰는 것만으로는 부족하고, 읽었다는 증거가 남아야 합니다. 또 사용 기록을 세어 보니, 만들어 둔 스킬 가운데 실제로 자주 쓰인 것은 손에 꼽을 만큼이었습니다. 스킬은 미리 많이 만들어 두는 것이 아니라, 세 번째 반복되는 일에서 태어나야 합니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다.

1. 윤하람 씨가 쓴 헌장 초안을 읽습니다. 모든 줄이 "무엇을 하라/하지 말라"로 끝나는지 봅니다.

   ```markdown
   # 하람 글방 헌장 (charter.md)

   ## 1. 먼저 할 일
   - 작업을 시작하면 이 문서와 index.md를 먼저 읽는다.
   - 답변 첫 줄에 이번에 열어 본 파일 이름을 적는다.

   ## 2. 지킬 것
   - 10_sources의 원본은 고치거나 지우지 않는다. 고칠 때는 사본에서 한다.
   - 확인하지 못한 날짜·인원·후기는 지어내지 않고 '확인 필요'로 남긴다.
   - 결과물은 deliverables/ 아래 '연월일_시분_영문주제' 폴더에 둔다.

   ## 3. 말투
   - 존댓말, 짧은 문장. 수강생을 평가하는 표현은 쓰지 않는다.

   ## 4. 사람이 정하는 것
   - 게시·발송·삭제는 하람 씨가 승인한 뒤에만 한다.

   ## 5. 스킬
   - 반복 작업은 skills/ 폴더에 해당 절차가 있는지 먼저 확인한다.
   ```

2. 내 헌장을 같은 다섯 장으로 쓰되, 장마다 1줄에서 3줄로 제한합니다. 넣고 싶은 말이 많으면 그것은 헌장이 아니라 스킬 후보입니다.

3. 최근 석 달 동안 세 번 이상 반복한 일 하나를 고릅니다. 하람 씨는 "강의 안내문 쓰기"를 골랐습니다.

4. 그 일의 스킬 초안을 씁니다. 첫머리에 이름과 "언제 쓰는지"를 적고, 본문에 내가 실제로 밟는 순서를 적습니다.

   ```markdown
   ---
   name: class-notice
   description: 기록·글쓰기 강의의 수강생 안내문을 쓸 때 사용한다. "모집 글", "안내문" 요청에 적용한다.
   ---
   # 강의 안내문 쓰기

   1. 30_decisions에서 지난 강의 관련 판단 기록을 먼저 읽는다.
   2. 다섯 문장으로 쓴다: 누구를 / 무엇을 / 어떻게 / 무엇이 남는지 / 준비물.
   3. 날짜·장소·참가비는 하람 씨가 이번에 준 값만 쓴다.
   4. 초안 끝에 '하람 씨가 확인할 것 3가지'를 붙인다.
   ```

5. 헌장을 폴더 맨 위에, 스킬을 `skills/class-notice/SKILL.md`에 저장합니다. 에이전트에게 아래 요청문을 건네고, 답변 첫 줄에 두 파일이 적혀 나오는지 확인합니다.

스킬에 보조 스크립트를 붙여 자동으로 돌리는 일은 C3 업무 자동화에서 다룹니다. 이 수업의 스킬은 절차 문서 한 장으로 충분합니다.

## AI에게 건네는 말

> 이 폴더의 charter.md를 먼저 읽고, 규칙을 다섯 줄로 요약해 줘. 답변 첫 줄에는 네가 실제로 열어 본 파일 이름을 적어 줘. 읽지 못한 파일이 있으면 그렇다고 말해 줘.

> skills/class-notice/SKILL.md의 절차대로 다음 달 강의 안내문 초안을 써 줘. 절차 중 따를 수 없었던 단계가 있으면 그 이유를 적고, 파일은 deliverables/ 아래 새 폴더에만 만들어 줘.

## 손에 남길 것과 완료 확인

**`charter.md` 한 장 · 스킬 폴더 한 개(`SKILL.md`)**

에이전트 답변 첫 줄에 헌장과 스킬 파일 이름이 실제로 적혀 있는지 확인합니다. 초안이 스킬의 네 단계를 따랐는지 단계마다 표시하고, 따르지 않은 단계가 있으면 스킬 문장이 모호했는지, 에이전트가 건너뛰었는지를 나눠 적습니다. 헌장을 읽었다는 증거가 없으면 완료로 적지 않습니다.
