# 9강. 실습 ② 내 워크스페이스 감사

유정근 · 마이웨이 아카데미 | C2 자료관리론

정본 교시: 2-5 1일차 통합 점검 & 개인 워크스페이스 감사(Audit)

## 오늘의 목표

내 자료가 흩어진 상태를 여섯 가지 기준으로 진단해 감사 결과표를 쓰고, 10강부터 에이전트(내 폴더의 파일을 직접 열어 보며 일하는 AI, C1의 AGY)에게 열어 줄 폴더 하나를 준비합니다.

## 먼저 이해하기

이사 전날 집 안을 한 바퀴 도는 일과 같습니다. 모든 짐을 정리하는 날이 아니라 무엇이 어디에 있는지, 무엇이 깨지기 쉬운지, 무엇을 새 집에 들이지 않을지를 확인하는 날입니다. <strong>감사</strong>(Audit — 정해진 기준으로 현재 상태를 점검해 기록하는 일)도 정리가 목적이 아닙니다. <strong>발견하고, 오늘 고칠 것과 나중에 고칠 것과 그대로 둘 것을 나누는 일</strong>입니다. <strong>워크스페이스</strong>는 내가 일에 쓰는 폴더와 저장소 전체를 말합니다.

오늘의 기준은 여섯 가지입니다.

1. 입구가 몇 개인가(저장소 수)
2. 같은 자료가 두 곳에 있지 않은가(중복 사본)
3. 에이전트가 글자로 읽을 수 있는 형식인가
4. 이름이 규칙을 따르는가
5. 정본(2강, 기준으로 삼는 한 벌)이 표시되어 있는가
6. 민감 자료(남의 개인정보, 계약서처럼 에이전트에게 보여 주지 않을 자료)가 작업 폴더 밖에 있는가

전부 한 번에 해결하려 하면 오늘 안에 끝나지 않습니다. 찾아서 적는 것까지가 오늘의 일입니다.

## 실제 기록에서 배운 한 줄

2강에서 본 동기화 사본은 강사가 검색 색인을 붙이려고 폴더를 하나하나 세어 보던 중에야 드러났습니다. 5강의 `.gdoc` 바로가기 제출물도 마찬가지로, 누군가 열어 보기 전까지는 멀쩡한 문서처럼 보였습니다. 감사는 이런 일이 작업 도중이 아니라 작업 전에 드러나게 하는 절차입니다.

## 가상 예시로 직접 해 보기

아래 인물·자료·기관은 학습용 가상 설정입니다.

1. **준비(3분)** 크롬에서 4강의 구글 시트 `자료지도` 와 3강의 `저장소지도` 문서를 탭으로 열어 둡니다. 파일 탐색기에서는 8강에서 만든 `my_work\(내 영문 이름)_space` 폴더를 엽니다. 결과를 적을 새 구글 문서를 `https://docs.google.com` → '빈 문서'로 만들고 제목을 `날짜_감사결과_v01` 로 바꿉니다. PC 시작 단추를 누르고 `시계` 를 입력해 '시계' 앱을 연 뒤, 왼쪽의 '타이머'에서 40분을 맞추고 시작합니다(휴대폰 타이머도 됩니다).

2. **입구 세기(5분)** 자료가 있는 저장소를 모두 적고 역할을 붙입니다(정본 / 작업본 / 공유본 / 백업). 3강 저장소 지도에서 빠진 곳이 없는지 휴대폰과 PC를 한 번 더 훑어봅니다. 윤하람 씨는 노트북 폴더, 클라우드 드라이브, 휴대폰 메모 앱, 메신저 나에게 보내기 네 곳을 적었습니다.

3. **중복 사본 찾기(5분)** 동기화되거나 복사된 같은 자료 묶음을 찾습니다.
   - 파일 탐색기에서 의심 가는 폴더에 마우스 오른쪽 단추 → '속성'을 누르면 '내용: 파일 ○개, 폴더 ○개'가 보입니다. 두 폴더의 숫자가 같으면 같은 묶음일 가능성이 큽니다.
   - 하람 씨는 클라우드 드라이브의 `강의자료_백업` 폴더가 노트북 폴더와 같은 내용임을 발견하고, 노트북 쪽을 정본으로 표시했습니다. 사본은 지우지 않고 "백업, 검색 제외"라고만 적습니다.

4. **형식 점검(5분)** 에이전트가 글자로 읽을 수 없는 자료를 표시합니다. 탐색기 위쪽 '보기' → '자세히'를 누르면 '유형' 칸이 보여 찾기 쉽습니다. 대표적인 것은 셋입니다.
   - `.gdoc`·`.gsheet` 바로가기(구글 문서·시트로 가는 주소표일 뿐 본문이 없음, C0 11강)
   - 사진으로만 찍힌 문서(글자가 그림이라 읽기 어려움)
   - 암호가 걸린 파일

   바꾸는 방법은 C0 11강에서 배웠으니, 오늘은 목록만 만듭니다.

5. **이름 점검(4분)** 날짜 이름 규칙(C0 4강 `날짜_내용_v01`)을 벗어난 파일 다섯 개를 고릅니다. 대괄호 `[ ]`·괄호 `( )`·`#` 같은 특수문자가 들어간 이름도 따로 표시합니다. 다음 수업에서 이것이 왜 문제가 되는지 봅니다.

6. **정본 점검(4분)** 제목이 같은 여러 버전 묶음 하나를 골라 정본을 표시합니다. 가장 최근 파일이 곧 정본은 아닙니다. 하람 씨의 `안내문_최종`과 `안내문_최종2` 중 실제로 게시한 것은 앞의 파일이었습니다.

7. **민감 자료 분리(4분)** 수강생 명단, 상담·후기 원문, 계약서처럼 에이전트에게 보여 주지 않을 자료가 `(내 영문 이름)_space` 폴더 안에 있는지 확인합니다. 있다면 옮길 위치를 적습니다(예: `my_work` 밖에 따로 만든 `private_files` 폴더). 오늘 바로 옮기지 못하면 "옮길 예정"으로 남깁니다.

8. **안내판 시험(5분)** 짝이 있으면 서로의 `index.md` 를 메일이나 메신저로 보내 바꿔 읽고, 상대가 지정한 자료 두 개를 찾아봅니다. 찾지 못한 자료는 어느 문장이 부족했는지 한 줄로 알려 줍니다. 짝이 없으면 8강 'AI에게 건네는 말'의 두 번째 글을 제미나이에 다시 보내되, 찾을 자료를 내 연대기의 다른 사건으로 바꿔 묻습니다.

9. **감사 결과표 작성(5분)** `감사결과` 문서에 '삽입' → '표'로 가로 5칸 표를 넣고 아래 형식으로 적습니다.

   | 기준 | 발견한 것 | 오늘 고친 것 | 10강 전에 고칠 것 | 그대로 둘 것과 이유 |
   |---|---|---|---|---|
   | ② 중복 사본 | 드라이브 백업 폴더 = 노트북 폴더 | 노트북 쪽 정본 표시 | 없음 | 백업은 유지, 검색에서만 제외 |
   | ③ 형식 | `.gdoc` 7개 | 없음 | 문서 형식으로 내려받기 | 없음 |

10. **에이전트용 폴더 선언(2분)** 에이전트에게 열어 줄 폴더 하나를 정합니다. 보통 8강의 `(내 영문 이름)_space` 입니다. 그 안에 글자로 읽히는 자료(`.md`, `.txt`, `.docx`, 글자가 든 `.pdf`)가 10개 이상 있는지 탐색기에서 세어 봅니다. 모자라면 `10_sources` 폴더에 원본의 <strong>사본</strong>을 복사해 넣습니다(원본 위에서 `Ctrl + C` → `10_sources` 안에서 `Ctrl + V`). 민감 자료가 없는지 다시 봅니다. 4강 사전 검색에서 실패한 문항이 있었다면 오늘 찾은 원인을 감사 결과표 옆에 적습니다.
   → 이렇게 보이면 됩니다: 폴더를 오른쪽 단추 → '속성'으로 열었을 때 파일이 10개 이상이고, 감사 결과표에 여섯 기준이 모두 한 줄씩 있습니다.

## AI에게 건네는 말

> **어디에 입력하나요:** PC에서 크롬을 열고 주소창에 `https://gemini.google.com` 을 입력해 들어갑니다. 구글 계정으로 로그인돼 있으면 화면 아래쪽에 글을 쓰는 입력칸이 보입니다. 그 칸을 한 번 누르고, 아래 글을 복사(`Ctrl + C`)해 붙여 넣은(`Ctrl + V`) 뒤 `Enter` 를 누르거나 오른쪽의 보내기(제출) 버튼을 누르세요. (여러 줄을 쓸 때는 `Enter` 대신 `Shift + Enter` 로 줄을 바꿉니다 — `Enter` 만 누르면 바로 보내집니다.) 답이 위쪽에 나타나면 끝까지 읽고, 모르는 말이 있으면 "○○가 무슨 뜻이야?" 라고 이어서 물으면 됩니다.
> 화면을 보여 주고 싶으면: 입력칸 왼쪽의 '+' 또는 파일 추가 버튼으로 캡처 이미지(C0 22강의 `Win + Shift + S`)를 올린 뒤 질문을 씁니다.

오늘은 에이전트가 아니라 제미나이에 **파일 이름 목록만** 건넵니다. 목록을 복사하는 방법:

1. 파일 탐색기에서 감사할 폴더를 엽니다.
2. 빈 곳을 한 번 누르고 `Ctrl + A` 로 모두 선택합니다.
3. `Ctrl + Shift + C` 를 누릅니다(선택한 파일에서 마우스 오른쪽 단추 → '경로로 복사'와 같습니다).
4. 제미나이 입력칸에 첫 번째 글을 붙여 넣고 `Shift + Enter` 로 줄을 바꾼 뒤 `Ctrl + V` 로 목록을 붙여 보냅니다.
   → 이렇게 보이면 됩니다: 입력칸에 `"C:\Users\(내 계정 이름)\my_work\…"` 처럼 따옴표로 묶인 줄이 파일 수만큼 들어갑니다. 파일 이름에 남의 이름이 들어 있으면 그 줄을 지우고 보냅니다.

> 이 폴더의 파일 목록만 보고 감사해 줘. 같은 내용으로 보이는 파일 묶음, 날짜 규칙을 벗어난 이름, 특수문자가 들어간 이름, 글자로 읽을 수 없는 형식을 표로 정리해 줘. 파일을 옮기거나 지우거나 이름을 바꾸지는 마.

두 번째 글은 같은 대화창에서, 감사 결과표를 문서에서 끌어 선택해 복사한 뒤 글 아래에 붙여 보냅니다.

> 감사 결과표 초안을 보고, 내가 '그대로 둔다'고 한 항목 중 10강 이후 에이전트 작업에 방해가 될 만한 것이 있는지 이유와 함께 알려 줘. 최종 결정은 내가 한다.

## 손에 남길 것과 완료 확인

**감사 결과표 1장 · 에이전트에게 열어 줄 폴더 1개**

- [ ] 저장소 목록에 모든 입구가 적혀 있고, 각각 역할이 붙어 있다
- [ ] 중복 사본 묶음이 있다면 정본 쪽이 표시되어 있다(없으면 "발견 없음")
- [ ] 에이전트가 읽을 수 없는 형식의 목록이 있다
- [ ] 제목이 같은 버전 묶음 하나에 정본이 표시되어 있다
- [ ] 민감 자료가 작업 폴더 밖에 있거나, 옮길 위치가 적혀 있다
- [ ] 짝(또는 AI)이 내 `index.md`만 보고 자료 두 개 중 몇 개를 찾았는지 적었다
- [ ] 에이전트에게 열어 줄 폴더에 글자로 읽히는 자료가 10개 이상 있다

체크하지 못한 항목은 비워 두고 "10강 전에 고칠 것" 칸으로 옮깁니다. 발견을 많이 한 결과표가 잘 쓴 결과표입니다.
