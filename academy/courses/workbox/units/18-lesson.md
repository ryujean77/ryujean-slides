# 18강. 시스템 구축 ⑭: GitHub 커밋·푸시

유정근 · 마이웨이 아카데미 | C5 단일 강좌 · 점검하고 공개하다

## 오늘의 목표

GitHub Desktop으로 `workbox` 폴더를 비공개 저장소에 올리고, 변경을 검토한 뒤 커밋·푸시해 버전 이력이 쌓이는 것을 확인합니다.

## 오늘 손에 남는 것

**산출물 ⑨ 비공개 작업 저장소의 GitHub 기록** — GitHub에 비공개 저장소 `workbox` 가 있고, 그 안에 커밋 두 건 이상이 이력으로 남은 상태입니다.

## 준비물

- 실습용 PC, 크롬, GitHub Desktop(`https://desktop.github.com` 에서 설치), AGY
- GitHub 계정(17차시 사전 과제로 만든 아이디·비밀번호 수첩)
- 17차시 기능·공개 점검표(모든 행 '통과')

## 먼저 이해하기

결재 문서 대장을 떠올려 보세요. 문서를 고칠 때마다 날짜·고친 사람·고친 이유를 한 줄 적어 두면, 석 달 뒤에도 "언제 무엇이 왜 바뀌었는지" 찾을 수 있습니다. Git(깃)은 이 대장을 컴퓨터가 대신 써 주는 도구입니다. GitHub(깃허브)는 그 대장과 파일을 온라인 금고에 보관해 주는 곳입니다. PC가 고장 나도 금고에는 남습니다.

용어 네 개만 알면 됩니다.

> **저장소(repository)** — Git이 이력을 관리하는 폴더 하나. 내 PC의 `workbox` 가 저장소가 되고, GitHub에도 같은 이름의 저장소가 생깁니다

> **커밋(commit)** — 지금 상태를 한 줄 설명과 함께 대장에 기록하는 일. 결재 도장에 해당합니다

> **푸시(push)** — 내 PC에 쌓인 커밋을 GitHub 금고로 보내는 일

> **비공개(Private)** — 나와 내가 초대한 사람만 볼 수 있는 저장소 상태

순서는 늘 같습니다. <strong>고친다 → 바뀐 파일을 검토한다 → 커밋한다 → 푸시한다</strong>. 커밋만 하고 푸시하지 않으면 기록은 내 PC에만 있습니다. 오늘은 AGY에게 git 명령을 시키지 않고, 눈으로 보며 누르는 GitHub Desktop 한 가지로 통일합니다.

## 따라 하기

**가. GitHub Desktop에 로그인하기**

1. '시작' 단추를 누르고 `GitHub Desktop` 을 쳐서 엽니다.
2. 위쪽 메뉴 'File' → 'Options'를 누릅니다.
3. 'Accounts' 칸에서 GitHub.com에 로그인하는 'Sign into' 버튼을 누릅니다.
4. 'Continue With Browser'를 누르면 크롬이 열립니다. 아이디와 비밀번호를 넣고 'Sign in'을 누릅니다.
5. 크롬에 나오는 안내를 따라 GitHub Desktop으로 돌아갑니다.
    → 이렇게 보이면 됩니다: 'Accounts' 칸에 내 아이디가 보입니다.

**나. `workbox` 를 저장소로 만들고 첫 커밋하기**

6. 'File' → 'Add local repository'를 누릅니다.
7. 'Choose...'를 누르고 `C:\사용자\(내 계정 이름)\workbox` 폴더를 고릅니다.
8. 아직 Git 저장소가 아니라는 안내와 함께 'create a repository' 링크가 보이면 그 링크를 누릅니다.
9. 새 저장소 창에서 'Name'이 `workbox` 인지 봅니다. 'Initialize this repository with a README'는 체크를 끕니다(README.md가 이미 있습니다). 'Create repository'를 누릅니다.
10. 왼쪽 'Changes' 칸에 파일 목록이 나옵니다. 한 줄씩 눌러 오른쪽 내용을 훑어봅니다. 이것이 <strong>변경 검토</strong>입니다.
    ✖ 이렇게 되면: 목록에 실명·연락처가 든 파일이 보이면 커밋하지 말고 17차시 다 단계로 돌아갑니다.
11. 왼쪽 아래 'Summary' 칸에 `17차시 점검 통과본` 이라고 씁니다.
12. 그 아래 'Commit to main' 버튼(브랜치 이름에 따라 'main' 자리가 다를 수 있습니다)을 누릅니다.

**다. 비공개로 올리기(푸시)**

13. 위쪽 'Publish repository'를 누릅니다.
14. 'Name'이 `workbox` 인지 보고, <strong>'Keep this code private'에 체크가 되어 있는지 반드시 확인</strong>합니다. 'Organization'이 보이면 'None'을 고릅니다.
15. 'Publish Repository'를 누릅니다.
16. 'Repository' 메뉴의 'View on GitHub'로 크롬을 엽니다.
    → 이렇게 보이면 됩니다: 저장소 이름 옆에 'Private' 표시가 있고, 내 파일 목록이 보입니다.

**라. 두 번째 커밋으로 이력 쌓기**

17. 아래 요청문을 AGY에게 보내 `README.md` 한 곳만 고칩니다.
18. GitHub Desktop의 'Changes' 칸에 `README.md` 한 줄이 생깁니다. 눌러 보면 더해진 줄이 초록색으로 보입니다.
19. 'Summary'에 `README 운영 기록 칸 추가` 를 쓰고 커밋합니다.
20. 위쪽 'Push origin'을 누릅니다.
21. 왼쪽 'History' 칸을 누릅니다.
    → 이렇게 보이면 됩니다: 커밋 두 줄이 날짜와 함께 보입니다. 크롬의 GitHub 화면을 새로 고쳐도 같은 기록이 보입니다.

(화면의 글자는 버전에 따라 조금 다를 수 있습니다.)

## AI에게 건네는 말

> **어디에 입력하나요:** '시작' 단추를 누르고 `Antigravity` 를 쳐서 AGY를 엽니다. 왼쪽에 `workbox` 프로젝트가 열려 있는지 먼저 봅니다. 화면 아래쪽 채팅 입력칸(에이전트에게 말을 거는 칸)을 누르고 아래 글을 붙여 넣은 뒤 `Enter` 로 보냅니다. AGY가 계획이나 권한 확인 카드를 먼저 보여 주면, 무엇을(동작) 어디에(대상) 하려는지 읽고 `workbox` 폴더 안의 일일 때만 허락합니다.

실제 고객 정보·주민번호·비밀번호·API 키는 AI에게도, 저장소에도 넣지 않습니다. 비공개 저장소라도 마찬가지입니다.

> `README.md` 맨 아래에 '운영 기록'이라는 제목을 만들고, 그 아래에 "날짜 / 바꾼 것 / 이유" 세 칸짜리 표를 만들어 줘. 첫 줄에 오늘 날짜와 "GitHub 비공개 저장소에 첫 기록"을 적어 줘. 다른 파일은 건드리지 말고, git 명령은 실행하지 마. 끝나면 바뀐 줄만 보여 줘. 확인용 테스트 스크립트는 따로 만들거나 실행하지 마.
