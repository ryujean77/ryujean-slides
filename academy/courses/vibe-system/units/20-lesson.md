# 20강. 시스템 구축 ⑯: 배포·시연·운영 규칙

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

공개용 저장소에 푸시 후 GitHub Pages URL을 점검하고 전 과정을 시연. 산출물 ⑩ 공개 시연 페이지와 개인 운영 규칙 완성

## 왜 이 단계가 필요한가

마지막에는 공개 가능한 흐름만 배포하고, 실제 업무 자료는 개인용 앱에 남깁니다.

## 따라 하기

1. 공개용 시연본을 별도의 공개 저장소에 푸시합니다.
2. 저장소 `Settings → Pages`에서 배포 원천을 확인하고 공개 URL을 엽니다.
3. 접수→검토→검색→산출물 시연과 주간 운영 규칙 1장을 발표합니다.

## 공개 확인

GitHub의 [Pages 배포 원천 설정 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)에 따라 공개용 저장소의 배포 원천을 선택합니다. 배포 후에는 내 PC가 아닌 다른 브라우저에서도 URL을 열어 봅니다. 페이지가 보인다는 사실과 Inbox→산출물 시연이 되는지는 따로 확인합니다.

주간 운영 규칙 1장에는 `Inbox 점검일`, `원본 확인 방법`, `승인 담당`, `백업·복구 방법`을 적습니다.


## AI에게 건네는 말

> 배포 전 공개용 폴더의 파일명과 내용에서 개인정보·비밀키·내부 원본의 흔적을 점검해 줘. 문제를 발견하면 배포 명령을 실행하지 말고 파일과 이유를 알려 줘.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 산출물 ⑩ 공개 URL에서 비식별 시연본이 열린다
- [ ] 개인 운영 규칙과 3분 시연을 마쳤다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
