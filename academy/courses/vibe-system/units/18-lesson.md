# 18강. 시스템 구축 ⑭: GitHub 커밋·푸시

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

변경 파일을 검토한 뒤 커밋·푸시하고 버전 이력을 확인. 산출물 ⑨ 비공개 작업 저장소의 GitHub 기록 완성

## 왜 이 단계가 필요한가

Git은 바꾼 이유를 남기는 이력입니다. 개인용 앱 코드는 비공개 작업 저장소에 기록합니다.

## 따라 하기

1. GitHub에 비공개 연습 저장소를 준비하고 로컬 프로젝트의 변경 파일을 검토합니다.
2. 터미널에서 `git status`, `git add`, `git commit`, `git push`를 순서대로 실행합니다.
3. GitHub 화면에서 커밋 제목과 파일 목록을 확인합니다. 개인 자료와 비밀키는 커밋하지 않습니다.

## 기록 순서

`git status`로 바뀐 파일을 확인합니다. 개인 데이터 파일을 제외한 뒤 `git add <검토한 파일>` → `git commit -m "feat: add inbox workflow"` → `git push` 순서로 진행합니다. 명령이 실패하면 오류 문구를 읽고 원인을 해결한 뒤 다시 시도합니다. `git add .`로 폴더 전체를 무심코 올리지 않습니다.


## AI에게 건네는 말

> 지금 변경 파일 목록을 읽고 커밋해도 되는 코드 파일과 제외할 개인 데이터 파일을 구분해 줘. 실제 git 명령을 실행하기 전 내가 목록을 승인할 때까지 기다려 줘.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 산출물 ⑨ 비공개 저장소에 커밋·푸시 기록이 있다
- [ ] 개인 자료·비밀키가 커밋에 없다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
