# 19강. 시스템 구축 ⑮: 공개용 시연본 분리

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

개인 자료와 내부 지식을 제외한 비식별 샘플 데이터·공개용 화면을 별도 배포본으로 구성

## 왜 이 단계가 필요한가

GitHub Pages의 화면은 공개됩니다. 개인용 데이터가 있는 작업본과 시연본을 별도로 만듭니다.

## 따라 하기

1. 공개용 폴더에 앱 화면과 가상 자료만 복사합니다.
2. 브라우저 저장 데이터·개인 경로·이름·토큰을 공개본에서 제거합니다.
3. 비식별 샘플 3건으로 Inbox→산출물 흐름이 시연되는지 확인합니다.

## 공개용 폴더 검수

- 공개 가능한 HTML·CSS·JavaScript만 있는가.
- 예시 데이터가 `가상`임을 분명히 표시했는가.
- 브라우저 localStorage의 개인 데이터는 복사되지 않았는가.
- 로컬 절대경로·고객 이름·연락처·비밀키가 없는가.

첫 방문자도 화면을 볼 수 있도록 **가상 샘플만** 첫 실행 시 넣는 방식을 사용합니다.


## AI에게 건네는 말

> 공개용 시연본의 파일 목록을 제안해 줘. 개인용 데이터·토큰·로컬 경로는 제외하고 가상 샘플만 남겨 줘. 제외한 목록을 먼저 보여 주고 내 확인 전에는 배포하지 마.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 공개용 폴더에 비식별 자료만 있다
- [ ] 개인용 지식저장소는 복사되지 않았다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
