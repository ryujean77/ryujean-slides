# 17강. 시스템 구축 ⑬: 기능 테스트와 공개 점검

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

Inbox→검색→산출물의 통합 흐름을 시험하고 오류 재현·수정, 개인정보·비밀키 포함 여부 점검

## 왜 이 단계가 필요한가

커밋 전에 기능과 공개 경계를 같이 확인합니다. 테스트는 결과가 맞는지 보여 주는 증거입니다.

## 따라 하기

1. Inbox 등록→검토→지식 카드→검색→산출물의 전체 흐름을 샘플로 실행합니다.
2. 빈 제목·중복 실행·반려·출처 누락 네 가지 실패 경로를 시험합니다.
3. 파일에서 이름·연락처·API 키·개인 로컬 경로를 검색해 공개 후보를 점검합니다.

## AI에게 건네는 말

> 이 프로젝트의 사용자 흐름과 실패 경로를 읽고 수동 테스트 체크리스트를 만들어 줘. 실제 파일을 삭제하거나 공개하지 말고, 실패한 항목은 원인과 재현 순서를 적어 줘.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 정상 흐름 1개와 실패 경로 4개를 확인했다
- [ ] 공개 후보에서 민감 정보 여부를 점검했다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
