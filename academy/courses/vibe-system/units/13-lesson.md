# 13강. 시스템 구축 ⑨: 자동화 실행 규칙

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

트리거·조건·액션을 코드 또는 설정으로 구현하고 입력값 검증·실패 시 재시도 조건 정의

## 왜 이 단계가 필요한가

트리거·조건·액션을 나눠야 예외가 생겼을 때 어느 단계에서 멈췄는지 알 수 있습니다.

## 따라 하기

1. 2차시 설계서의 트리거 하나와 조건 두 개를 골라 적습니다.
2. `자료 등록→검토 요청` 흐름을 구현하고 누락 입력은 중단합니다.
3. 같은 자료를 두 번 실행할 때 중복 처리가 생기는지 확인합니다.

## AI에게 건네는 말

> 기존 앱에 설계서의 한 흐름만 구현해 줘. 입력 누락 시 중단하고, 같은 id를 두 번 처리해도 기록이 중복되지 않게 해 줘. 실행 결과를 성공·보류·실패로 구별해 줘.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 정상 1건과 누락 1건의 결과가 다르다
- [ ] 중복 실행해도 새 기록이 무한히 늘지 않는다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
