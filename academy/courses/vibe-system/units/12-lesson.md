# 12강. 구축 ⑧: 대시보드 데이터 연결

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

실제 Inbox 건수·업무 상태 표시와 화면 이동. 산출물 ⑥ 개인 대시보드 완성

## 왜 이 단계가 필요한가

설계한 화면이 실제 Inbox 상태를 읽어야 대시보드가 됩니다.

## 따라 하기

1. 대기 건수·진행 중 건수·최근 산출물을 기존 데이터에서 계산합니다.
2. 각 카드에서 해당 목록으로 이동하게 합니다.
3. 샘플 자료 하나의 상태를 바꾼 뒤 대시보드 숫자가 갱신되는지 봅니다.

## 숫자 검수 예시

가상 자료 3건 중 `신규`가 2건이고 `검토`가 1건이라면 대기 건수는 설계에서 정한 기준대로 계산되어야 합니다. 신규 1건을 검토로 바꾼 뒤 화면 숫자가 달라지는지 확인합니다. 단순히 `3`이라는 숫자를 화면에 직접 적어 놓으면 통과가 아닙니다.


## AI에게 건네는 말

> 승인한 화면 설계대로 대시보드를 구현해 줘. 새 가짜 숫자를 하드코딩하지 말고 현재 localStorage 데이터에서 계산해 줘. Inbox 상태를 바꾸면 새로고침 후 숫자가 맞는지 확인해 줘.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 산출물 ⑥ 대시보드의 네 영역이 보인다
- [ ] Inbox 상태 변경이 표시 건수에 반영된다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
