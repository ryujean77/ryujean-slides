# 4강. 업무자동화 설계: AI 요구사항 명세

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

트리거·조건·액션, 사람 승인 지점, 수용 기준(Acceptance Criteria) 작성. 산출물 ② 업무자동화 설계서 완성

## 왜 이 단계가 필요한가

AI에게 맡길 범위와 사람이 멈춰 확인할 지점을 적어야 코드가 과하게 움직이지 않습니다.

## 따라 하기

1. `02_업무자동화_설계.md`에 입력→판단→처리→출력 흐름을 그립니다.
2. 트리거·조건·액션과 승인·반려·오류 경로를 적습니다.
3. 샘플 자료 1건으로 검증할 수용 기준 세 가지를 문장으로 씁니다.

## 설계서에 넣을 다섯 줄

1. **입력:** 어떤 자료가 어디로 들어오는가.
2. **판단:** 사람과 프로그램이 각각 무엇을 결정하는가.
3. **출력:** 파일 이름과 내용의 필수 칸은 무엇인가.
4. **예외:** 빈 값·중복·실패 때 어디에서 멈추는가.
5. **완료 기준:** 샘플을 넣었을 때 눈으로 확인할 결과 세 가지.

이 다섯 줄이 비어 있으면 다음 강에서 AI에게 구현을 부탁하기 전에 먼저 채웁니다.


## AI에게 건네는 말

> 아래 업무 흐름을 개발 요청서로 정리해 줘. 입력 항목, 처리 규칙, 사람이 승인할 지점, 실패 시 멈춤, 테스트 기준 3개를 포함하고 구현은 아직 하지 마.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 산출물 ② 설계서 1장을 저장했다
- [ ] 다른 사람이 읽고 성공·실패를 판정할 기준 3개가 있다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
