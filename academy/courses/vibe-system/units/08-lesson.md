# 8강. 시스템 구축 ④: Inbox 처리 상태

유정근 · 마이웨이 아카데미 | C4 단일 강좌

## 오늘의 목표

신규→검토→보관/반려 처리, 사람 확인·근거 기록. 산출물 ④ 분류 흐름 완성

## 왜 이 단계가 필요한가

처리 상태가 없으면 Inbox는 쌓이기만 합니다. 반려와 보관도 같은 흐름의 결과로 남겨야 합니다.

## 따라 하기

1. 상태를 `신규→검토→보관/반려`로 제한합니다.
2. 보관·반려 때 짧은 판단 근거를 입력하게 합니다.
3. 샘플 3건을 각각 처리하고 상태와 근거가 다시 열리는지 봅니다.

## 상태 전이 표

| 현재 | 허용되는 다음 상태 | 사람의 기록 |
|---|---|---|
| 신규 | 검토 | 분류 제안 확인 |
| 검토 | 보관 또는 반려 | 결정 이유 |
| 보관·반려 | 종료 | 원본 기록 유지 |

`신규→보관`처럼 검토를 건너뛰면 완료로 표시하지 않습니다.


## AI에게 건네는 말

> 기존 Inbox에 신규·검토·보관·반려 상태 전이를 추가해 줘. 보관 또는 반려할 때 사유가 비어 있으면 멈춰 줘. 자동 삭제는 만들지 마.

AI의 완료 보고만 믿지 말고 화면·파일·저장 결과를 직접 확인합니다.

## 완료 확인

- [ ] 산출물 ④ 분류·처리 흐름에서 3건의 최종 상태가 보인다
- [ ] 각 판단 근거가 남는다

이 과정의 예시 자료는 모두 학습용 가상 자료입니다. 실제 고객 기록·연락처·비밀번호를 공개 AI나 시연본에 넣지 않습니다.
