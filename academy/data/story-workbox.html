C5 · 20차시 · 「나의 업무함」 하나를 끝까지

코딩 없이 AI를 부려 내 업무용 도구를 만들고, 그 결과를 책임지고 검증하는 사람

AI 코딩 도구 AGY에게 말로 시켜 업무용 웹앱 하나를 20차시 동안 한 칸씩 키웁니다. 코드는 AI가 쓰고, 다 됐는지는 내가 판정합니다.

  • 20차시 · 앱 하나
  • 27개 복사용 요청문
  • 2번 처음부터 끝까지 시범 실행
  • 15개 차시별 완성본 제공

20차시 동안 앱이 이렇게 자랍니다

  1. 1~4차시 · 설계. 자료관리 규칙을 정하고, 반복 업무 하나를 고르고, "이렇게 되면 완성"이라는 기준을 적습니다.
  2. 5~8차시 · 접수함(Inbox). 들어온 자료를 등록하고 분류·검토·보관합니다.
  3. 9~12차시 · 지식 카드와 대시보드. 보관한 자료를 출처가 보이는 카드로 만들고, 검색과 한눈에 보는 화면을 붙입니다.
  4. 13~16차시 · 자동 처리 규칙. 민감한 자료는 자동으로 검토로 보내고, 사람이 승인한 기록을 남기고, 제미나이로 보고서 초안을 받습니다.
  5. 17~20차시 · 점검과 공개. 개인정보를 점검하고 GitHub에 기록을 남긴 뒤, 공개 시연 페이지를 웹 주소로 배포합니다.

수강생이 실제로 만드는 화면

교안 요청문을 그대로 AGY에 넣어 만든 화면입니다(가상 자료, 2026-10-21 시범 실행). AGY는 같은 요청에도 모양을 조금씩 다르게 만듭니다.

무엇을 배우나

1

AI에게 일을 맡기는 요청 쓰기

범위를 정하고, 한 번에 한 가지만 시키고, "테스트 스크립트는 만들지 마" 같은 제약을 붙입니다. 고칠 때는 고칠 곳 하나만 말합니다.

"원본 위치를 비워도 저장이 돼. 저장 전 검사에서 원본 위치 빈칸을 막는 부분만 고쳐 줘. 다른 기능은 바꾸지 마."
2

AI의 결과를 믿지 않고 확인하기

수용 기준을 먼저 적고, 크롬에서 직접 눌러 보고, 권한 카드에서 AI가 무엇을 어디에 하려는지 읽고 허락합니다.

3

업무를 시스템으로 쪼개기

트리거·조건·액션으로 규칙을 적고, 사람이 승인하는 지점과 예외에서 멈추는 곳을 먼저 정합니다.

4

자료를 다루는 원칙

원본과 사본을 구분하고, 민감도를 공개·내부·민감 세 단계로 나누고, 출처를 남기고, 공개본과 개인본을 분리합니다.

5

보관하고 공개하기

GitHub Desktop으로 변경 이력을 남기고, 개인정보를 뺀 시연본을 웹 주소로 공개합니다.

배우고 나면 할 수 있는 것

  • 내 업무 하나를 같은 방식으로 도구로 만듭니다. 접수 → 분류 → 승인 → 문서 작성 흐름이 있는 일이면 됩니다. 예: 교육 신청 관리, 견적서 정리, 회의록 정리.
  • AGY에게 기능을 더하거나 고치게 시키고, 제대로 됐는지 스스로 판정합니다.
  • "AI가 만든 걸 그대로 믿으면 안 되는 곳"을 압니다. AI가 실명을 기본값으로 넣거나, 시험 파일을 남기거나, 계획만 보여 주고 멈추는 경우를 직접 겪어 봅니다.
  • 포트폴리오가 생깁니다. 웹 주소로 보여 줄 수 있는 공개 시연 페이지와 GitHub 기록이 남습니다.
