# ④ 브라우저 업무·매일 아침 보고 자동화 스타터 키트

> **분류:** KIT 04 · 브라우저 · 예약 작업 · 아침 보고
> **목적:** 사이트 확인, 신청 수집, 공고 모니터링을 한 번 손으로 성공시킨 뒤 매일 보고로 예약합니다.

---

## 1. 현장 합격/성공 공식 & 폴더에 넣을 원형 자료

- **한 번 성공하고 예약:** 사이트와 저장 위치를 한 번 확인한 다음 /schedule로 반복합니다.
- **보고는 바로 행동하게:** 숫자만 모으지 말고 오늘 전화하거나 신청할 일을 맨 위에 둡니다.
- **읽기와 실행의 경계:** 조회·정리는 맡기고 신청·결제·발송은 사람이 승인합니다.

### 📁 작업 폴더(`workbox/`) 투입 원형 자료

- `01_확인할_사이트.txt` — 사이트 주소와 확인할 메뉴
- `02_보고_양식.md` — 받고 싶은 제목·항목·순서
- `03_승인_기준.md` — 에이전트가 혼자 하면 안 되는 일

---

## 2. 매일 보고 자동화 설계서

### 1. 모을 정보
- 가이드: 공고·예약·신청·통계
- 작성(예시): 새 정부 사업 공고의 이름·마감일·자격·주소

### 2. 확인할 곳
- 가이드: 주소와 메뉴
- 작성(예시): [사이트 주소]의 사업공고 게시판

### 3. 시각과 받는 곳
- 가이드: 주기·이메일
- 작성(예시): 평일 오전 9시, 내 이메일

### 4. 맨 위에 볼 것
- 가이드: 오늘 할 행동
- 작성(예시): 마감 7일 이내이면서 내가 자격이 되는 공고

### 5. 사람 승인선
- 가이드: 자동으로 하지 않을 일
- 작성(예시): 신청서 제출, 고객 연락, 결제, 글 게시

## 3. 바로 복사해 쓰는 실전 요청문 (프롬프트)

### 요청문 1. 예약 전 1회 시험 수집 요청문 (AGY · 브라우저)
- **언제 쓰나요:** 자동화를 처음 만들 때

```text
[사이트 주소]를 브라우저로 열어 [확인할 정보]를 한 번만 수집해 줘.
로그인이 필요하면 멈추고 내가 직접 로그인할 때까지 기다려.

수집한 항목, 확인한 주소와 시각을 표로 정리해 [저장 경로]에 새 파일로 저장해.
못 읽은 항목은 빈칸으로 숨기지 말고 '확인 불가'와 이유를 적어.
신청, 결제, 예약 확정, 메시지 발송은 하지 마. 끝나면 매일 반복해도 되는지 판단을 알려 줘.
```

### 요청문 2. 매일 아침 보고 예약 요청문 (/schedule)
- **언제 쓰나요:** 시험 수집 결과가 맞을 때

```text
/schedule [평일 오전 9시]마다 방금 확인한 절차로 [정보]를 수집해 [내 이메일]로 보고해 줘.

보고 순서는 오늘 할 일, 새 항목, 변경·마감 임박, 확인 실패 순서로 해.
어제와 같은 항목은 새 항목으로 세지 말고 모든 항목에 원문 주소를 붙여.
새 내용이 없어도 '없음'으로 보고해서 멈춘 것과 구분되게 해.
이메일 연결이나 권한이 더 필요하면 예약 전에 나에게 알려 줘.
```

### 요청문 3. 보고가 안 왔을 때 원인 확인 요청문 (AGY · 점검)
- **언제 쓰나요:** 예약된 시각에 결과가 없을 때

```text
[작업 이름]의 오늘 보고가 오지 않았어.
실행 기록을 먼저 읽고 예약이 실행됐는지, 컴퓨터 절전, 로그인 만료, 사용 한도나 결제, 사이트 변경, 이메일 전달 순서로 확인해 줘.
추측과 기록으로 확인한 사실을 구분해서 쉬운 말로 알려 줘.
고치기 전에 무엇을 바꿀지 설명하고, 고친 뒤에는 한 번 시험 실행한 증거를 보여 줘.
```

## 4. 사람 승인(Human-in-the-Loop) 최종 검수 점검표

- [ ] 보고된 날짜·자격·숫자를 원문 주소에서 확인했는가?
- [ ] 비밀번호와 고객 개인정보가 파일·요청문에 남지 않았는가?
- [ ] 신청·결제·연락은 자동 실행되지 않게 막았는가?
- [ ] 새 내용이 없는 날과 고장 난 날을 구분할 수 있는가?
