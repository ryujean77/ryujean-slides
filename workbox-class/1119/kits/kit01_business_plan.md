## 1. 현장 합격/성공 공식 & 폴더에 넣을 원형 자료

- **파일 열 개면 폴더 하나:** 샘플과 공고문을 한 폴더에 모아 폴더 경로를 주면 파일마다 복사할 필요가 없습니다.
- **두서없이 말하고 정리는 맡기기:** 마이크로 구상을 편하게 말하고, 정리한 뒤 부족한 것을 되물어 달라고 합니다.
- **목표는 검수할 수 있게:** 분량·필수 항목·심사 기준을 숫자와 문장으로 적어야 /goal이 어디까지 갈지 압니다.

## 2. 사업계획서 목표·완료 기준 설계서

### 1. 사업 한 문장
- 가이드: 누구의 어떤 문제를 어떻게 푸는가
- 작성(예시): 컴퓨터가 낯선 60대 이상이 AI 에이전트로 자기 업무 결과물을 만들도록 교육한다.

### 2. 제출처와 읽는 사람
- 가이드: 기관·사업명·심사위원
- 작성(예시): [사업명] 심사위원. 실현 가능성과 지속 가능성을 본다.

### 3. 내 역량과 증거
- 가이드: 파일로 보여 줄 수 있는 경험
- 작성(예시): 강의 교안과 수강생 실습 결과물 [파일 경로]

### 4. 기간·예산·인력
- 가이드: 모르면 미정으로 남김
- 작성(예시): 3개월 운영 / 예산 미정 / 강사 1명

### 5. 완료 기준
- 가이드: 분량, 필수 장, 근거 표시
- 작성(예시): 양식의 모든 항목을 채우고, 근거 없는 수치는 0건, 미정 항목은 따로 목록으로 만든다.

### 6. 반드시 물어볼 것
- 가이드: AI가 결정하면 안 되는 일
- 작성(예시): 예산, 협력기관, 실적 수치, 최종 제출

## 3. 바로 복사해 쓰는 실전 요청문 (프롬프트)

### 요청문 1. 샘플 폴더 공통 형식 추출 요청문 (AGY · Claude Code)
- **언제 쓰나요:** 자료를 모아 폴더 경로를 복사한 직후

```text
[폴더 경로]는 이번 사업계획서를 위해 모은 자료야.

1. 공고문에서 자격, 기한, 필수 항목, 심사 배점을 표로 정리해 줘.
2. 선정 샘플에서 공통으로 나오는 요소와 목차, 근거 제시 방식을 추려 줘.
3. 샘플의 실적과 문장은 내 것으로 옮기지 마.
4. 내 계획서에 적용할 목차와, 아직 나에게 없는 자료 목록을 만들어 줘.

각 판단 옆에 어느 파일의 어느 부분을 보았는지 적고, 아직 본문은 쓰지 마.
```

### 요청문 2. 두서없는 구상 정리와 빈칸 질문 요청문 (음성 입력 · 역질문)
- **언제 쓰나요:** 마이크로 내 생각을 말한 뒤

```text
지금부터 말하는 내용은 두서가 없는 사업 구상이야.
[여기에 말로 입력한 내용]

내가 말한 것을 목적, 대상, 수행 방법, 내 역량, 기간, 예산, 기대 효과로 정리해 줘.
말하지 않은 사실은 채우지 말고 '미정'으로 표시해.
심사위원 눈높이에서 빠진 내용을 중요한 순서로 한 번에 하나씩 물어봐.
내 답을 받을 때마다 정리본을 갱신해 주고, 다 채워지면 본문을 쓰기 전에 계획부터 보여 줘.
```

### 요청문 3. 완료 기준까지 작성·자체 검수 요청문 (/goal · 완성)
- **언제 쓰나요:** 계획을 확인하고 실제로 쓸 때

```text
/goal [제출양식 경로]에 사업계획서를 완성한다.

완료 기준:
- 양식의 모든 항목과 [목표 쪽수]를 충족한다.
- 수치와 실적에는 [자료 폴더 경로] 안의 근거 파일을 밝힌다.
- 근거 없는 내용은 지어내지 않고 확인 필요 목록에 남긴다.
- 원본 양식은 보존하고 새 파일로 저장한다.

다 쓴 뒤 완료 기준과 하나씩 대조해 표로 보고해 줘. 외부 제출은 하지 마.
```

## 4. 사람 승인(Human-in-the-Loop) 최종 검수 점검표

- [ ] 샘플의 실적·수치·문장이 내 것처럼 옮겨지지 않았는가?
- [ ] 예산과 기간, 자격 요건을 공고 원문과 직접 대조했는가?
- [ ] 빈 서식 원본을 보존하고 완성 파일을 실제 프로그램으로 열어 봤는가?
- [ ] 개인정보를 확인한 뒤 제출 버튼은 내가 눌렀는가?
