# ③ 브라우저 조사·비교 보고서 스타터 키트

> **분류:** KIT 03 · 조사 · 검색·비교 보고서
> **목적:** 에이전트가 실제 사이트를 열어 찾고 비교한 결과를, 기준이 적힌 보고서로 받습니다.

---

## 1. 현장 합격/성공 공식 & 폴더에 넣을 원형 자료

- **직원 한 명에게 시키듯 기준을 준다:** 가격대, 출시 시기, 정렬 순서처럼 기준을 주면 에이전트가 사이트를 직접 뒤지고 비교합니다. 기준이 흐리면 결과도 흐립니다.
- **에이전트가 잡은 기준을 확인한다:** 수업에서 에이전트는 ‘AI 노트북’의 기준을 스스로 정해 찾았습니다. 그 기준이 내 뜻과 맞는지 보고, 아니면 더 구체적인 기준을 줘서 다시 시킵니다.
- **검색은 맡기고 결제는 내가:** 검색·비교·정리는 에이전트가, 구매와 신청 같은 최종 결정은 사람이 합니다. 가격은 날마다 바뀌니 결정 전에 다시 확인합니다.

### 📁 작업 폴더(`workbox/`) 투입 원형 자료

- `01_조사_목적.md` — 무엇을 왜 찾는지, 결과를 어디에 쓸지
- `02_비교_기준.md` — 가격대·기간·필수 조건·제외 조건
- `03_내_상품_정보.xlsx` — (선택) 경쟁 비교라면 내 상품 정보

---

## 2. 조사·비교 기준 설계서

### 1. 찾을 대상
- 가이드: 무엇을 몇 개
- 작성(예시): 최신 AI 노트북 3종

### 2. 필수 조건
- 가이드: 숫자로
- 작성(예시): 200만원 이하, 최신 출시순

### 3. 제외 조건
- 가이드: 섞이면 안 되는 것
- 작성(예시): 해외 직구, 구형 모델

### 4. 볼 사이트
- 가이드: 로그인이 필요한가
- 작성(예시): 네이버 쇼핑 가격비교

### 5. 보고서 형식
- 가이드: 어디에 쓸 것인가
- 작성(예시): 표가 든 md, 끝에 추천 이유 세 줄

## 기준 다듬기 대조표

첫 결과가 마음에 안 들 때 더할 기준입니다.

| 첫 결과의 문제 | 더할 기준 |
| --- | --- |
| 오래된 모델이 섞임 | 출시 연도나 기간 |
| 너무 넓게 찾음 | 사양 조건(예: 그래픽카드 등급) |
| 근거가 없음 | 결과마다 출처 주소를 붙이라는 조건 |

---

## 3. 바로 복사해 쓰는 실전 요청문 (프롬프트)

### 요청문 1. 기준을 주고 비교 조사 맡기기 (에이전트 · 조사)
- **언제 쓰나요:** 사이트에서 찾고 비교할 때

```text
에고 라이트 브라우저로 [사이트]에서 [찾을 대상]을 [개수]개 찾아 줘.
필수 조건: [가격대, 사양, 기간]
제외 조건: [섞이면 안 되는 것]
1. 네가 잡은 판단 기준을 먼저 한 줄로 적어 줘.
2. 결과는 이름·가격·핵심 사양·출처 주소를 표로.
3. 조건에 맞는 것이 부족하면 억지로 채우지 말고 부족하다고 말해 줘.
4. 구매·신청은 하지 마.
```

### 요청문 2. 조사 결과를 보고서로 (에이전트 · 보고서)
- **언제 쓰나요:** 비교표를 받은 뒤

```text
방금 조사한 결과로 보고서를 만들어 줘. 파일은 작업 폴더에 [보고서 이름].md로.
1. 맨 위에 조사 목적과 기준, 조사한 날짜.
2. 비교표와 각 항목의 출처 주소.
3. 내 목적([목적])에 비춰 추천 하나와 이유 세 줄, 아쉬운 점 한 줄.
4. 가격처럼 바뀌는 정보에는 "조사일 기준"이라고 표시해 줘.
확인하지 못한 정보는 [확인 필요]로 남겨 줘.
```

## 4. 사람 승인(Human-in-the-Loop) 최종 검수 점검표

- [ ] 에이전트가 잡은 판단 기준이 내 뜻과 같은가?
- [ ] 결과마다 출처 주소가 붙어 있는가?
- [ ] 조건에 안 맞는 것을 억지로 채우지 않았는가?
- [ ] 구매·신청 같은 최종 결정은 내가 했는가?
