# ④ 반복 업무 자동화 설계 스타터 키트

> **분류:** KIT 04 · 설계 · 반복 업무 자동화
> **목적:** 교재 279~282쪽 방식으로 반복 업무를 고르고, 입력·판단·처리·출력으로 쪼갠 뒤 트리거·조건·액션 설계서를 만듭니다.

---

## 1. 현장 합격/성공 공식 & 폴더에 넣을 원형 자료

- **반복되는 일만 자동화한다:** 1년에 한두 번 하는 일은 그때 시키면 됩니다. 자주 하고, 순서가 늘 같고, 시간이 꽤 들고, 옮겨 적다 실수가 나는 일 가운데 셋 이상이면 자동화 대상입니다.
- **판단과 약속은 사람 손에:** 사람의 판단이 매번 다른 일, 밖으로 돈이나 약속이 나가는 일은 자동화하지 않고 사람이 합니다. 설계서에 사람 확인 지점을 꼭 적습니다.
- **반복은 대화가 아니라 스킬로:** 매번 대화로 시키면 에이전트는 늘 새 일로 받아들입니다. 설계가 굳으면 스킬로, 토큰을 아끼려면 파이썬 프로그램으로 만듭니다.

### 📁 작업 폴더(`workbox/`) 투입 원형 자료

- `01_업무_목록.md` — 요즘 하는 업무를 반복·계속·끝남으로 나눈 목록
- `02_고른_업무_순서.md` — 자동화할 업무 하나의 순서(이름·연락처 없이)

## 2. 업무 자동화 설계서

### 1. 고른 업무
- 가이드: 네 조건 중 셋 이상 해당하는가
- 작성(예시): 매주 들어오는 신청 메일 명단 정리

### 2. 입력
- 가이드: 누가, 무엇을, 어디로
- 작성(예시): 신청 메일이 Gmail로 들어온다

### 3. 판단
- 가이드: 어떤 기준으로
- 작성(예시): 신청 조건(지역·인원)에 맞는지 본다

### 4. 처리
- 가이드: 무엇을 바꾸거나 옮기나
- 작성(예시): 명단 표에 옮겨 적는다

### 5. 출력
- 가이드: 결과를 어디로
- 작성(예시): 확인 메일 초안을 만들어 나에게 보여 준다

### 6. 트리거·조건·액션
- 가이드: 언제·무엇이면·무엇을
- 작성(예시): 매일 9시, 제목에 '신청'이 있으면, 명단에 추가하고 나에게 알린다

## 3. 바로 복사해 쓰는 실전 요청문 (프롬프트)

### 요청문 1. 교재 280쪽 업무 분석 요청문 (에이전트·챗봇 · 예외 찾기)
- **언제 쓰나요:** 네 단계를 적은 뒤

```text
너는 사무 업무 분석가다. 아래는 내가 반복하는 업무를 입력·판단·처리·출력 네 단계로 적은 것이다.
내가 놓쳤을 수 있는 예외 상황을 단계마다 두 개씩 질문 형태로 물어봐 줘.
내가 적지 않은 단계를 새로 만들지 말고, 답은 '단계 / 놓쳤을 수 있는 예외 / 확인 질문' 세 칸 표로 줘.
모르는 업무 용어가 있으면 추측하지 말고 나에게 물어봐.

입력: [ ]
판단: [ ]
처리: [ ]
출력: [ ]
```

### 요청문 2. 트리거·조건·액션 설계 후 스킬로 만드는 요청문 (에이전트 · 설계서와 스킬)
- **언제 쓰나요:** 예외까지 정리한 뒤

```text
[02_고른_업무_순서.md]와 예외 표를 바탕으로 자동화 설계서를 만들어 줘.
1. 트리거(언제), 조건(무엇이면), 액션(무엇을)을 문장으로.
2. 사람이 확인할 지점과 자동화하지 않을 일을 따로 표시.
3. 가장 단순한 버전부터 시작하고, 확장 버전은 나중 단계로 나눠 줘.
4. 내가 승인하면 이 설계를 스킬로 만들어 줘. 토큰을 아낄 수 있는 부분은 파이썬 프로그램으로 바꿀 수 있는지도 알려 줘.
승인 전에는 실행하지 마.
```
